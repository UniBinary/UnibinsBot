* *侦测器（Observer）**是当一个面对的方块传来状态更新时会发出红石信号的方块。

# 生成
侦测器不会生成在世界中。

# 破坏
挖掘侦测器的合适工具是镐。侦测器需要木镐或品质更好的镐来挖掘，否则挖掘时间将延长且不会掉落。

侦测器被破坏后会掉落自身。

# 用途
侦测器的放置方式类似于[活塞](活塞.md)，放置后其输出红石信号的一端会朝向玩家。它会侦测其侦测面对着的方块。侦测面是侦测器的“脸”。由于侦测器可以侦测其他侦测器的状态，因此放置两个侦测面相邻的侦测器（彼此侦测）可以制作紧凑的高频红石时钟。详见[侦测器高频](Tutorial:高频电路#侦测器高频.md)。

# = 行为 =
侦测器用于侦测目标方块的方块状态的变化，或者方块的放置或移除（方块状态的改变，而**不是**方块实体数据的改变）。
侦测器充当方块更新检测器的角色，它会响应面前造成[PP更新](方块更新#PP更新.md)的事件。尽管侦测器能够阻挡[光](亮度.md)，但它不是红石导体：它不能被外部红石信号充能，也不能被自己的输出信号充能。
* 注意，由于Java版与基岩版的机制差异，两个版本分别有另一个版本不能侦测到的变化，详见下文的表格。

当侦测到某变化时，侦测器会向输出面发出[信号强度](红石电路.md)为15，持续2[游戏刻](游戏刻.md)的脉冲。脉冲能激活[红石粉](红石粉.md)、[红石中继器](红石中继器.md)、或在侦测器输出端一侧的[机械元件](红石元件.md)等，也会强充能输出端朝向的红石导体至15等级。

侦测器侦测到变化后延迟**2游戏刻**后激活，亮起后再过**2游戏刻**后关闭。

实际体现为**2红石刻**。原因是基岩版侦测器信号计算阶段为**电容器更新阶段**而非信号源更新阶段（这使得输出“延后”了1红石刻）。<ref></ref><ref></ref>

当关闭的侦测器本身被活塞移动到位后，侦测器在移动到位后再过2游戏刻会发出脉冲；若活塞推动时侦测器是激活的，则不会在移动到位后发出脉冲。

由于侦测器可以侦测方块状态变化，而非方块更新（[NC更新](方块更新#NC更新.md)），它相较于BUD可以侦测范围更广的现象（因为一些方块状态的改变不会引起方块更新）。

侦测器有时会侦测方块更新，有时会侦测方块状态的改变。如侦测红石粉时，侦测器侦测其信号强度方块状态变更，连接变更（无论是红石粉链接变化还是其涉及的有向图变化）则不会被侦测。

侦测器是典型的[计划刻](刻#计划刻.md)元件，其行为依赖计划刻事件，当侦测器执行计划刻事件时，若侦测器是关闭状态，则激活，若侦测器是激活状态，则关闭，具体行为如下：
* 侦测器在面前的方块状态发生变化（发出PP更新）时，会添加一个延迟为**2游戏刻**的计划刻事件，在2游戏刻后执行该计划刻事件。依次执行以下操作：
* # 将自身方块状态设为激活（powered:false->true）
* # 发出状态更新（PP更新）
* # 添加延迟2游戏刻的计划刻事件
* # 发出方块更新（NC更新）
* 在2游戏刻后，侦测器执行计划刻事件，此时侦测器为激活状态，依次执行以下操作：
* # 将方块状态设为关闭（powered:true->false）
* # 发出状态更新（PP更新）
* # 发出方块更新（NC更新）<ref></ref>

侦测器被活塞推动时：
* 关闭的侦测器被活塞推动后，在[移动的活塞](移动的活塞.md)变为侦测器时，会添加一个延迟2游戏刻的计划刻事件。
* 激活的侦测器被活塞推动时，会停止信号输出，并在后方输出位置发出方块更新（NC更新）。
在[移动的活塞](移动的活塞.md)变为侦测器时：
* 若在到位位置**没有**侦测器的计划刻事件，则状态设为关闭，向后方输出位置发出方块更新（NC更新），不会添加计划刻事件。
* 若在到位位置**有**侦测器的计划刻事件，则侦测器状态保持激活，不会向后方输出位置发出方块更新（NC更新），直到执行该计划刻事件时状态设为关闭。

侦测器的计划刻优先级均为0（NORMAL）。
