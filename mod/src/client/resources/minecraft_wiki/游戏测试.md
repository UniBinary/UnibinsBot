# 游戏测试

*页面ID: 170135* | *来源: Minecraft Wiki*

* *游戏测试（GameTest或Game Test）**是用于测试游戏各项行为的[](wzh:集成测试.md)。<ref name="25w03a"></ref>

游戏测试系统是一个较独立的游戏系统，被设计于在标准[超平坦世界](超平坦世界.md)中运行，与其他游戏系统共同运行会导致未定义的行为。<ref name="25w03a"/><ref></ref>

# Java版
# = 测试实例 =

* *测试实例（Test Instance）**定义了单个测试的基本信息。包括**测试环境（Test Environment）**、测试结构和测试的成败条件等。

测试环境是游戏运行测试的游戏环境，例如特定的[天气](天气.md)、[昼夜时间](昼夜更替.md)和[游戏规则](游戏规则.md)等。

测试实例有**基于方块的测试（Block-Based Test）**和**内置函数测试（Built-in Function Test）**两种。前者依赖于测试结构的[测试方块](测试方块.md)，后者依赖于硬编码的测试函数。

测试实例和测试环境可由[数据包](数据包.md)加载，但测试函数必须通过[Mod](Mod.md)加载。

# == 运行测试实例 ==
测试实例可以被[测试实例方块](测试实例方块.md)运行。在测试实例方块的界面中输入测试实例的ID，点击“加载并运行”按钮后此测试实例方块就会运行输出的测试实例。游戏会在测试实例方块上渲染不同颜色的信标光柱标识测试的运行与成败。

命令控制了游戏测试的多项行为，包括测试的创建和运行，它也可以批量运行测试。

除此之外，游戏内置了测试服务端，它可以自动运行所有可用的测试实例。

# = 测试服务端 =
测试服务端位于[客户端核心文件](客户端核心文件.md)和[服务端核心文件](服务端核心文件.md)内，作为可运行主类存在于两种文件的代码中。

测试服务端的类名为<code>net.minecraft.gametest.Main</code>。

# == 启动参数 ==
因为核心文件清单文件中定义的主类并非测试服务端类，所以必须指定JVM参数运行测试服务端。

如果要运行测试服务端，需要下列命令：

下列为测试服务端启动参数：
* <code>--help</code>：输出测试服务端的命令帮助。此参数具有最高优先级，其他参数会被此项参数忽略。
* <code>-{}---packs <*路径*></code>：指定存档要使用的[数据包](数据包.md)的目录。在此目录下任何具有有效[数据包元数据](pack.mcmeta.md)的文件夹或zip压缩包均会被游戏视为有效数据包。
* <code>-{}---report <*路径*></code>：指定类似于JUnit的XML报告导出的路径，名称相同时会替换已有的报告。
* <code>-{}---tests <*选择*></code>：指定要运行的测试。不指定或指定空ID时默认可运行所有测试，格式参见。
* <code>-{}---universe <*路径*></code>：指定存档的目录。默认为<code>gametestserver</code>，名称相同时会替换已有的存档。
* * 存档自身的名称为<code>gametestworld</code>，不可修改。
* <code>-{}---verify <*布尔值*></code>：是否启用测试验证，默认为<code>false</code>。启用时，每个测试的每个角度（0、90、180、270）均会各运行100次。

# == 世界行为 ==
测试服务端创建的服务端世界存档名为“Test Level”，允许命令，默认游戏模式为创造模式，世界为标准超平坦世界。

初始化世界完成后，游戏会根据传入参数筛选出所有可用的测试实例，排除掉所有手动运行（为<code>true</code>）的测试实例后，在世界的<code>[-14999992, -59, -14999992]</code>至<code>[14999992, -59, 14999992]</code>范围内随机选取一处作为世界出生点，并从此处开始自动运行测试，每行运行8个。

# == 日志监测 ==
测试服务端启动时世界内没有任何玩家，故不能直接查看测试的结果，但是游戏会将测试的结果输出到日志中。

如果测试未开始，则开始测试。每经过20游戏刻，游戏会输出一行文本，按照单个测试的加载顺序展示测试结果：
* 测试结构的总格式为<code>[ ... ]</code>，由一对方括号括起，其中的每个字符都代表一个测试。
* * 如果测试未开始，则对应的位置输出空白字符。
* * 如果测试成功，则对应的位置输出<code>+</code>。
* * 如果测试失败，则检测测试是否必须成功（为<code>true</code>），如果是则对应的位置输出<code>X</code>，否则输出<code>x</code>。
* * 其他情况下（如测试已经开始但尚未结束）对应的位置输出<code>_</code>。

如果没有任何可以进行的测试，或者所有测试均测试完毕，那么测试服务端会自动停止运行。服务端停止运行后会再次按上述格式输出测试的结果，同时输出总结性的日志，包括测试的成功数量和失败数量等，失败的测试也会输出测试信息和失败信息。

# 基岩版

基岩版的游戏测试系统被称为**游戏测试框架（GameTest Framework）**，游戏测试由[附加包](附加包.md)驱动，测试函数使用JavaScript编写。这些测试可由命令运行。

Mojang提供了一系列与游戏测试框架相关的文档和实例：

* [<code>@minecraft/server-gametest</code>脚本API文档](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server-gametest/minecraft-server-gametest)
