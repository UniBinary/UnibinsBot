# 环境属性

*页面ID: 168793* | *来源: Minecraft Wiki*

* *环境属性（Environment Attribute）**是根据不同环境来控制各种视觉效果和游戏机制等玩法的机制。

# 环境属性
环境属性提供了基于不同环境而具有不同游戏玩法和视觉效果的机制。所谓“环境”，即**环境属性源（Environment Attribute Source）**，目前游戏共有四个环境属性源，按照应用顺序依次为[维度](维度.md)、[生物群系](生物群系.md)、[时间线](时间线.md)和[天气](天气.md)。

维度和天气提供了全局的环境属性，时间线提供了基于时间的环境属性，生物群系提供了基于特定位置的环境属性。

# = 修饰符 =
不同的环境属性源可能提供相同的环境属性，游戏会将其叠加操作后作为实际应用的环境属性，而**修饰符（Modifiers）**决定了叠加操作的方式。

修饰符的可用值取决于具体的环境属性，所有的环境属性均具有**覆盖操作（<code>override</code>）**这一种修饰符，其效果为仅应用最后一个应用的环境属性。

例如：若主世界维度指定天空颜色为蓝色，平原生物群系指定天空颜色为绿色，其他主世界生物群系未定义天空颜色，则玩家在主世界的平原生物群系时，天空颜色为绿色；在主世界的其他生物群系时，天空颜色为蓝色。

# = 插值 =
部分环境属性可插值，当玩家在环境属性不同的区域间移动时，游戏不会立刻切换环境效果，而是会对其进行平滑过渡。游戏会在插值计算时一并应用修饰符。

环境属性的可插值是其固有性质，游戏并不总是进行插值计算。目前游戏会在下列情况下使用插值：
* 计算以摄像机坐标解析的环境属性。在摄像机周围半径10格内占据区域最多的生物群系会对插值产生最大的影响。
* 计算时间线的环境属性轨道。根据属性轨道和时间进行插值。

例如：若主世界维度指定云层高度为100，平原生物群系指定云层高度为1700，其他主世界生物群系未定义云层高度，则摄像机在主世界的平原生物群系与其他生物群系的交界处时云层高度可以是100至1700之间的任何值，但对于快乐恶魂而言云层高度只有100和1700两个值。

# 环境属性列表
# = 视觉效果 =

这些环境属性主要影响游戏的视觉效果。

# == visual/fog_color ==
控制[迷雾](迷雾.md)的颜色。迷雾的最终颜色也会被[昼夜更替](昼夜更替.md)、[药水效果](药水效果.md)等因素影响。

数据类型为[RGB颜色](#RGB颜色.md)，默认值为，可使用[RGB颜色修饰符](#RGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/fog_start_distance ==
控制迷雾的起始距离，以方块为单位。迷雾的起始距离是迷雾从完全透明到开始有影响的距离，如果为负数，则迷雾将初始存在，就像它从摄像机后面开始产生影响一样。迷雾的最终起始距离也会受天气等因素影响。

数据类型为，默认值为<code>0.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/fog_end_distance ==
控制迷雾的结束距离，以方块为单位。迷雾的结束距离也被称为可见距离，是迷雾达到最大浓度的距离，超过结束距离后迷雾将完全不透明。迷雾的最终结束距离也会受天气等因素影响，且不会小于96格。

数据类型为，且必须大于0，默认值为<code>1024.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/sky_fog_end_distance ==
控制天空迷雾的结束距离，以方块为单位。

数据类型为，且必须大于0，默认值为<code>512.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/cloud_fog_end_distance ==
控制云层迷雾的结束距离，以方块为单位。

数据类型为，且必须大于0，默认值为<code>2048.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/water_fog_color ==
控制[水下迷雾](迷雾#水下迷雾.md)的颜色。水下迷雾的最终颜色也会被昼夜更替、药水效果等因素影响。

数据类型为[RGB颜色](#RGB颜色.md)，默认值为，可使用[RGB颜色修饰符](#RGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/water_fog_start_distance ==
控制水下迷雾的起始距离，以方块为单位。如果为负数，则迷雾将初始存在，就像它从摄像机后面开始产生影响一样。

数据类型为，默认值为<code>-8.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/water_fog_end_distance ==
控制水下迷雾的结束距离，以方块为单位。水下迷雾的最终结束距离也和玩家在水下的时长有关。

数据类型为，且必须大于0，默认值为<code>96.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/sky_color ==
控制天空颜色。

数据类型为[RGB颜色](#RGB颜色.md)，默认值为，可使用[RGB颜色修饰符](#RGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/sunrise_sunset_color ==
控制[日出日落效果](天空#日出日落效果.md)颜色。如果完全透明则不会渲染日出日落效果。日出日落效果仅在<code>overworld</code>天空盒下才会渲染，在天空东侧还是西侧渲染取决于太阳的位置。

数据类型为[ARGB颜色](#ARGB颜色.md)，默认值为，可使用[ARGB颜色修饰符](#ARGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/cloud_color ==
控制[云层](云层.md)颜色。如果完全透明则不会渲染云，且实体也不会认为自身在云中，例如[快乐恶魂](快乐恶魂.md)对云层的判定。

数据类型为[ARGB颜色](#ARGB颜色.md)，默认值为，可使用[ARGB颜色修饰符](#ARGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/cloud_height ==
控制云层高度。如果云层透明度不为0，则实体在世界界限内、云层高度至云层高度之上4格内的区域时会认为自身在云中。

数据类型为，默认值为<code>192.33</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/sun_angle ==
控制[太阳](太阳.md)的高度角，单位为度，为0时恰好在摄像机正上方，从东到西顺时针计算。太阳仅在<code>overworld</code>天空盒下才会渲染。它也影响[时钟](时钟.md)的角度和[阳光探测器](阳光探测器.md)的部分计算。

数据类型为，默认值为<code>0.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值。解析位置如下：
* 天空中的太阳渲染：摄像机位置。
* 物品模型：物品持有者的位置。
* 阳光探测器：阳光探测器的位置。

# == visual/moon_angle ==
控制[月亮](月亮.md)的高度角，单位为度，为0时恰好在摄像机正上方，从东到西顺时针计算。月亮仅在<code>overworld</code>天空盒下才会渲染。

数据类型为，默认值为<code>0.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/star_angle ==
控制[星星](星星.md)的高度角，单位为度，为0时恰好在摄像机正上方，从东到西顺时针计算。星星仅在<code>overworld</code>天空盒下才会渲染。

数据类型为，默认值为<code>0.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/moon_phase ==
控制[月相](月相.md)，包括月亮渲染、月亮亮度、物品模型等一系列与月相相关的机制。

数据类型为字符串枚举，默认值为<code>full_moon</code>，仅接受<code>override</code>修饰符。不可插值，解析位置如下：
* 天空中的月亮渲染：摄像机位置。
* 物品模型：物品持有者的位置。
* 月亮亮度计算：对应的位置。

可用枚举值如下：
* <code>full_moon</code>（满月）
* <code>waning_gibbous</code>（亏凸月）
* <code>third_quarter</code>（下弦月）
* <code>waning_crescent</code>（残月）
* <code>new_moon</code>（新月）
* <code>waxing_crescent</code>（峨眉月）
* <code>first_quarter</code>（上弦月）
* <code>waxing_gibbous</code>（盈凸月）

# == visual/star_brightness ==
控制星星的亮度。在原版定义下夜晚为0.5，白天为0。

数据类型为，且必须在0至1之间，默认值为<code>0.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/block_light_tint ==

控制方块光照的色调。方块光照颜色在低光照下为灰色，中等光照时会被此属性染色，高等级光照时为白色。该色调适合明亮的颜色，适用于所有的光源，但单个光源无法拥有不同的色调。技术上而言此环境属性提供了着色器lightmap的参数<code>BlockLightTint</code>。

数据类型为[RGB颜色](#RGB颜色.md)，默认值为，可使用[RGB颜色修饰符](#RGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/sky_light_color ==
控制[天空光照](天空光照.md)的视觉颜色。对于天空光照为0或环境属性<code>visual/sky_light_factor</code>为0的区域没有任何效果。技术上而言此环境属性提供了[着色器lightmap](着色器#lightmap.md)的参数<code>SkyLightColor</code>。

数据类型为[RGB颜色](#RGB颜色.md)，默认值为，可使用[RGB颜色修饰符](#RGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/sky_light_factor ==
控制天空光照的视觉亮度。天空光照的最终渲染将使用环境属性<code>visual/sky_light_color</code>的颜色乘上此值。技术上而言此环境属性提供了着色器lightmap的参数<code>SkyFactor</code>。

数据类型为，且必须在0至1之间，默认值为<code>0.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/night_vision_color ==

影响夜视光照的颜色，R、G、B每个通道都会选择此属性和<code>visual/ambient_light_color</code>属性提供的通道的最大值。技术上而言此环境属性提供了着色器lightmap的参数<code>NightVisionColor</code>。

数据类型为[RGB颜色](#RGB颜色.md)，默认值为，可使用[RGB颜色修饰符](#RGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/ambient_light_color ==

控制环境光照的颜色。技术上而言此环境属性提供了着色器lightmap的参数<code>AmbientColor</code>。

数据类型为[RGB颜色](#RGB颜色.md)，默认值为，可使用[RGB颜色修饰符](#RGB颜色修饰符.md)。可插值，解析位置为摄像机的位置。

# == visual/default_dripstone_particle ==
控制[滴水石锥](滴水石锥.md)上方没有液体时滴落的默认粒子。

数据类型为[粒子选项](粒子数据格式.md)，默认值为<code>{"type": "minecraft:dripping_dripstone_water"}</code>，仅接受<code>override</code>修饰符。不可插值，解析位置为滴水石锥的位置。

# = 游戏玩法 =

这些环境属性主要影响游戏的游戏玩法。

# == gameplay/sky_light_level ==
控制天空光照的强度。只影响诸如幻翼生成、阳光探测器计算、生物生成光照等游戏行为，不影响任何游戏亮度渲染属性。

数据类型为，且必须在0至15之间，默认值为<code>15.0</code>，可使用[浮点修饰符](#浮点修饰符.md)。可插值，**无解析位置，在整个维度内解析**。

数据类型较复杂（见下），仅接受<code>override</code>修饰符。不可插值，解析位置为床头的位置。

<div class="treeview">
*
* * ：床可以入睡的条件。取值可以为<code>always</code>（总是成功）、<code>when_dark</code>（[内部天空光照](内部天空光照.md)不大于11时成功）和<code>never</code>（总是失败）。

</div>

# == gameplay/monsters_burn ==
控制生物是否会自行[着火](着火.md)。此环境属性不会同步到客户端。

生物着火取决于下列因素，所有的条件必须满足，否则不会着火：
* 不是玩家、玩家模型或盔甲架，且属于实体类型标签。
* 生物所处位置的<code>gameplay/monsters_burn</code>环境属性值为<code>true</code>。
* 生物不处于水中、雨中或细雪中。
* 生物眼睛位置的天空光照为15。
* 设当前生物眼睛位置的内部光照是*i*，维度环境光照为*a*，则<math>\frac{60a-4ai+i}{60-3i}</math>大于0.5。
* 生物的头盔槽位（僵尸马和僵尸鹦鹉螺使用身体盔甲槽位判断）没有任何物品。

数据类型为，默认值为<code>false</code>，可使用[布尔修饰符](#布尔修饰符.md)。不可插值，解析位置为生物的位置。

# 环境属性修饰符
* *环境属性修饰符（Environment Attribute Modifiers）**是游戏进行修饰操作的方法。游戏在进行环境属性之间的计算时，会使用到3个参数：
* **输入值**：此上下文将被修改的值。
* **参数值**：修饰符进行修饰时的附加参数。
* **修饰符类型**

不同的场合会使用不同的修饰符格式，但都具有这三个参数，其中输入值由游戏自动获取，参数值必须手动提供，修饰符类型可选。

为便于展示，下文使用环境属性映射的格式展示修饰符。

# = 覆写修饰符 =
“覆写（override）”即直接使用一个新的值覆盖相应的环境属性值。

当直接设置一个环境属性ID到其对应值的映射时，将隐式使用<code>override</code>修饰符：
<div class="treeview">
* ：要设置的环境属性值。需要与相应环境属性的数据类型对应。
</div>

或者也可以显式定义<code>override</code>修饰符：
<div class="treeview">
*
* * ：<code>override</code>
* * ：要设置的环境属性值。需要与相应环境属性的数据类型对应。
</div>

能够使用以下通用修饰符的环境属性都可以使用覆写修饰符来直接设值。

# = 布尔修饰符 =
此类修饰符用于修饰布尔值。

<div class="treeview">
*
* * ：要应用的布尔修饰符。
* * ：提供的布尔值，用于修饰符计算。
</div>

可用修饰符如下：
* <code>and</code>：[操作](wzh:逻辑与.md)，仅当输入值与参数值均为<code>true</code>时为<code>true</code>。
* <code>nand</code>：[操作](wzh:逻辑与非.md)，仅当输入值与参数值均为<code>true</code>时为<code>false</code>。
* <code>or</code>：[或操作](wzh:逻辑或.md)，仅当输入值与参数值均为<code>false</code>时为<code>false</code>。
* <code>nor</code>：[操作](wzh:逻辑或非.md)，仅当输入值与参数值均为<code>false</code>时为<code>true</code>。
* <code>xor</code>：[操作](wzh:逻辑异或.md)，仅当输入值与参数值不同时为<code>true</code>。
* <code>xnor</code>：[操作](wzh:当且仅当.md)，仅当输入值与参数值相同时为<code>true</code>。

# = 浮点修饰符 =
此类修饰符用于修饰浮点数。

<div class="treeview">
*
* * ：要应用的浮点修饰符。
* *
* * ：用于修饰符计算的参数。指定为浮点数时默认仅指定<code>value</code>。
* ** ：[线性插值](wzh:线性插值.md)区间的终点。
* ** ：（，默认为1）插值的取样点。
* *
* * ：提供的浮点数，用于修饰符计算。
</div>

可用修饰符如下：
* <code>add</code>：将输入值与参数值作和。
* <code>subtract</code>：将输入值与参数值作差。即输入值减去参数值。
* <code>multiply</code>：将输入值与参数值作积。
* <code>minimum</code>：取输入值与参数值的最小值。
* <code>maximum</code>：取输入值与参数值的最大值。
* <code>alpha_blend</code>：在输入值和<code>value</code>的区间内进行线性插值计算。
* * <code>alpha</code>为1时，实质上就是覆盖操作。

# = 颜色修饰符 =

此类修饰符用于修饰颜色。不论是哪种修饰符，每个通道的计算结果都会钳制在<code>[0, 255]</code>之间。

颜色修饰符分为两类：RGB颜色修饰符和ARGB颜色修饰符，分别修饰RGB颜色和ARGB颜色。

<div class="treeview">
*
* * ：要应用的颜色修饰符。
* *
* * ：提供的ARGB颜色，用于修饰符计算。
* **
* *
* * ：提供的ARGB颜色，用于修饰符计算。
* ** ：（）应用到灰度值的倍率。
* ** ：（）计算使用的因子。
* *
* *
* * ：提供的颜色，用于修饰符计算。
* **
* *
* * ：提供的颜色，用于修饰符计算。如果提供RGB颜色，则不允许字符串格式，游戏会将其A通道视为255。
* **
* **
</div>

可用修饰符如下：
* <code>add</code>：将输入值与参数值作和。每个通道单独计算。
* <code>subtract</code>：将输入值与参数值作差。即输入值减去参数值，每个通道单独计算。
* <code>multiply</code>：将输入值与参数值作积。每个通道单独计算。
* <code>alpha_blend</code>：对颜色进行[alpha混合](wzh:alpha混合.md)。对于输入值的通道K而言的计算结果为<code>K * (1 + A/255)</code>，R、G、B、A四个通道均进行计算。
* * A通道为1时，实质上就是使用参数值进行覆盖操作。
* <code>blend_to_gray</code>：对输入值进行灰度处理，计算的亮度和因子由参数提供。
* * 先计算灰度<code>gray</code>：<code>brightness * (0.3 * R + 0.59 * G + 0.11 * B)</code>，其中RGB为输入值的通道值。
* * 再计算输出值的对应通道：<code>-{}-lerp(factor, <*输入颜色对应通道*>, gray)</code>，即输入颜色的对应通道与灰度区间上以因子作为采样点经线性插值得到的值。

# 天气环境属性
天气环境属性源被硬编码。游戏会先判断当前维度是否允许拥有天气（为<code>true</code>、为<code>false</code>且当前维度不是末地），如果允许才会应用天气环境属性。
