# 区域文件格式

*页面ID: 9269* | *来源: Minecraft Wiki*

* *区域文件**（**Region File**）是Minecraft中保存[区块数据](区块存储格式.md)的一种方式。

# 区域
一个区域文件存储的范围被称为**区域**（**Region**）。一个区域的大小是32×32[区块](区块.md)，并且区块坐标与32对齐。

区域坐标和区块坐标的换算只需要进行移位操作（即除以32并向下取整），下列代码演示了这个算法：

<syntaxhighlight lang="java">
int regionX = chunkX >> 5;
int regionZ = chunkZ >> 5;
</syntaxhighlight>

区块在一个区域内的局部坐标（下文简称为局部坐标）只需要对原始区块坐标对32取，下列代码演示了这个算法：

<syntaxhighlight lang="java">
int regionLocalX = chunkX & 0x1F;
int regionLocalZ = chunkZ & 0x1F;
</syntaxhighlight>

举例来说，坐标为（30, -3）的区块位于（0，-1）的区域中；而坐标为（70, -30）的区块位于（2，-1）的区域中。

游戏在使用区域文件存储时，先将每个区块内的数据分开为方块数据、[实体数据](实体数据格式.md)和[兴趣点数据](兴趣点存储格式.md)。这三种数据在逻辑上是一体的，但在存储时它们被分隔到各个目录形成不同文件位置但逻辑位置相同的文件。

区域文件的命名与存储的区域有关。如果区域的坐标为<code>(regionX, regionZ)</code>，则区域文件的名称为。

# 文件结构
区域文件的长度永远与**扇区**（**Sector**）对齐，即大小永远可以被4KiB整除。

区域文件主要分为两部分：文件头和区块数据。

# = 文件头 =
文件头一共8KiB，分为两个数据块：前4KiB用于存储区块存储位置偏移和占用扇区数，后4KiB用于存储区块数据时间戳。

如果文件大小小于8KiB，那么游戏会认为这个区域文件无效，并在日志中输出“Region file <*区域文件*> has truncated header: <*文件大小*>”报错信息。

# == 区块保存顺序 ==
在文件头的两个数据块内，区块都以固定顺序保存。

将4KiB的数据块4个字节为一组，就能形成1024，即32×32个区块的信息。区块信息从局部坐标(0, 0)开始写入（即作为下标0，或第一个），按照局部X坐标递增写入区块信息，直到局部X坐标到达31；之后递增一次局部Z坐标，再次以局部X坐标递增，直到局部X坐标到达31。重复上述操作，最后将所有区块信息排列到这1024组内部。

以数学表示，如果区块的局部坐标为<code>(x, z)</code>，那么它所在的下标就是<code>x+32z</code>。

# == 区块存储位置偏移和占用扇区数 ==
对于一个区块对应的一组数据，前3个字节用于保存区块信息保存的起始扇区偏移，后1个字节保存这个区块占用了多少个扇区。在这里，一个扇区为4KiB。

由于占用扇区数被保存为一个字节，所以在区域文件中区块数据最多只能保存255×4KiB（1020KiB）。如果超出了这个数字，游戏会使用额外文件辅助保存这个区块（见下文）。

区域文件最多保存1024个区块，如果所有区块都保存了1020KiB数据，那么可以得出区域文件最大大小为1044488KiB（0.996GiB）。

起始扇区偏移是从文件开始计算的，即第一个区块数据的偏移为2，剩余的区块数据偏移也至少为2。

如果起始扇区偏移和占用扇区数都为0，则代表对应区块不存在或未创建。

# == 区块时间戳 ==
对于一个区块对应的一组数据，使用大端序保存[纪元秒](wzh:UNIX时间.md)（Epoch seconds）。

区块时间戳保存了一个区块最后被修改的时间，如果一个区块未被创建过则为0。

# = 区块数据 =
每个区块数据的前五个字节为区块元信息，后面才是真正的区块内部数据。

数据长度从压缩类型（即第5个字节）开始计算，用于标识区块内部数据的真实长度。由于区块数据必须按照扇区保存，未保存数据的位置需要留空，而长度用于标记哪些部分是有效数据，哪些数据是无效的留空。

压缩类型表示了后方的数据使用了什么样的压缩算法。目前一共有4种压缩算法：

在通常情况下，游戏默认以数值2，即Zlib压缩算法压缩区块数据。通过修改[server.properties](server.properties.md)中的<code>region-file-compression</code>，可以让游戏以LZ4格式（数值4）压缩区块数据，也可以选择不压缩数据（数值3）。GZip格式在游戏中并未实际应用。

如果使用数值127，那么在后方数据的头部必须有一个以[变种UTF-8](https://docs.oracle.com/en/java/javase/17/docs/api/index.html#modified-utf-8)保存的[命名空间ID](命名空间ID.md)，且需要第三方服务器自行实现压缩算法。

如果区块在压缩后，区块数据长度（包括数据长度的4字节）大于1020KiB，则区域文件无法完整保存这个区块。这种情况下，此区块的数据长度会被写为1，压缩类型字段的**最高位**会被修改为1（相当于加上了128），并且游戏会创建额外文件{{filename|-{}-c.<*区块X坐标*>.<*区块Z坐标*>.mcc}}存储区块数据（前5个字节会被留空），在日志中输出“Saving oversized chunk <*区块坐标*> (<*区块数据大小*> bytes} to external file <*额外文件路径*>”代表此区块已经被额外存储。
