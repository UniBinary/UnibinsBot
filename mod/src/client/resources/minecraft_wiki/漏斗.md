# 漏斗

*页面ID: 9529* | *来源: Minecraft Wiki*

</ref>||Duncan Geere Mojavatar.png}}

* *漏斗（Hopper）**是一种可以用来捕捉物品实体或用来把[物品](物品.md)传入或移出容器的[方块](方块.md)。

# 生成
# = 自然生成 =
漏斗会生成于[试炼密室](试炼密室.md)每个决斗室的入口，充当弃物装置。

# 破坏
挖掘漏斗的合适工具是镐。漏斗需要木镐或品质更好的镐来挖掘，否则挖掘时间将延长且不会掉落。

漏斗被破坏后会掉落自身和内容物。

# 用途
[漏斗可朝向下或旁边|缩略图](File:Hopper-Aligment.png.md)

漏斗可用作容器、合成材料以及红石元件。

漏斗的底部有一个“输出”管，它可以朝向下或朝向侧边，可以直接看出漏斗输出方向。要放置漏斗，对着漏斗输出方向面对的方块表面，即可使漏斗的输出管指向该方向。在一个可以互动的方块表面放置漏斗时，还要按下键。对着方块下表面放置漏斗也会使漏斗朝向下。漏斗在放置后不能改变朝向，也不能“附着”它所朝向的容器。朝向的容器被破坏，漏斗也不会改变方向。

尽管漏斗的[方块支撑形状](方块支撑形状.md)上表面不完整，但[铁轨](铁轨.md)、[红石粉](红石粉.md)、可以放在漏斗上面。

# = 容器 =

漏斗可用作容器，它有5个物品槽位。

对漏斗按下可以打开漏斗的界面。

[红石比较器](红石比较器.md)可检测漏斗存储物品的数量。

漏斗界面的标题默认为“漏斗”，可在放置前使用[铁砧](铁砧.md)重命名来进行更改，也可以通过使用命令修改漏斗的<code>CustomName</code>标签进行更改（例如要把一个位于(0,64,0)的漏斗标记为“Alice的漏斗”，则使用{{cmd|data merge block 0 64 0 {CustomName:'"Alice的漏斗"'} }}）。

漏斗可被<code>lock</code>标签上锁。若漏斗的该标签不是空白的，那么这个漏斗必须使用符合该标签表示的物品谓词的物品打开。

# = 红石元件 =

漏斗可用来吸入在它上方的物品实体，或运输物品。

漏斗是一种[红石元件](红石元件#机械元件.md)，它可通过下列方式激活：
* 毗邻的开启的**[电源](红石元件#电源元件.md)**（例外：侦测器只会激活指向的漏斗，）。
* 毗邻的**[充能方块](红石电路/充能与激活.md)**。
* 毗邻的指向漏斗且激活的[红石中继器](红石中继器.md)、[红石比较器](红石比较器.md)或红石粉（包括漏斗上方的红石粉）；毗邻但未指向漏斗的红石粉不会激活漏斗。

在同一红石刻内，电容器更新阶段前存在，但在电容器更新阶段被取消的信号无法激活漏斗。

漏斗的行为与多数红石元件相反，它在**未**被激活时进行工作，在被激活时停止工作。因此，未激活的漏斗会被描述为**开启**，激活的漏斗会被描述为**关闭**。

# == 开启的漏斗 ==
开启的漏斗会尝试进行以下操作：
* **输出**自己物品栏里的1个物品到朝向的容器。
* * 每次进行输出时，漏斗只会尝试输出1个物品，且优先尝试输出靠左槽位里的物品，并将其放在容器靠上一行中的靠左槽位里。
* * 若容器内所有槽位都有物品，但某种物品还未达到堆叠上限时，漏斗会在自己的物品栏里寻找一个能够与之堆叠的物品并尝试输出。
* **吸取**上方容器中的1个物品到自己的物品栏。
* * 每次进行吸取时，漏斗只会尝试从上方容器中吸取1个物品，且优先尝试吸取容器靠上一行中的靠左槽位里的物品。
* * 若漏斗内所有槽位都有物品，但某种物品还未达到堆叠上限时，漏斗会在上方容器中寻找1个能够与之堆叠的物品并尝试吸取。
* **捕捉**上方的1个[物品实体](物品实体.md)到自己的物品栏。
* * 每次进行捕捉时，漏斗只会捕捉凹槽内以及上方1×1×1范围内的1个物品实体（无论其堆叠了多少个物品）。物品实体即使只有一部分在可捕捉位置（如位于漏斗上方[碰撞箱](碰撞箱.md)不完整的方块上或位于漏斗边缘），也会被漏斗捕捉。
* * 漏斗还可以在[熔岩](熔岩.md)摧毁物品实体之前或玩家捡起物品实体之前将其捕捉。
* * 若上方是容器或，漏斗就不会尝试检查和捕捉物品实体（可用于减少卡顿），但凹槽内的物品实体会主动进入漏斗。
* * 若漏斗内所有槽位都有物品，但某种物品还未达到堆叠上限时：
* ** 由于不同的漏洞，漏斗此时可能无法再捕捉物品实体。
* ** 漏斗会在上方寻找一个能够与之堆叠的物品实体并尝试捕捉。
* * 若漏斗无法捕捉物品实体中的所有物品，该物品实体中剩余的物品将保持实体状态。

漏斗总是尝试把吸取或捕捉的物品放在靠左的可用槽位里。

在一个游戏刻内，漏斗会先尝试输出，然后尝试吸取，最后在上方没有容器时尝试捕捉物品实体。在以上尝试完成后，只要有一个操作成功进行，漏斗就会进入“冷却时间”，即在等待之后才会进行下次操作。另外，当其他漏斗或投掷器将物品输入此漏斗时，此漏斗也会进入的冷却时间。

在一些情况下，漏斗的冷却时间为而非：
* 该漏斗正在向另一个漏斗输出物品。
* 输出的漏斗内没有物品。
* 输出的漏斗早于该漏斗接收游戏刻执行逻辑。
* 输出的漏斗没有自定义冷却，即不大于8。
当满足上述所有条件时，输出的漏斗冷却时间会被设置为，以保证漏斗传输的时序一致。

若漏斗尝试向空漏斗传输物品，则空漏斗接收到该物品后的冷却时间为，否则没有冷却时间。

漏斗不能与[末影箱](末影箱.md)进行交互。

# == 关闭的漏斗 ==
关闭的漏斗类似于一个普通的容器（如木桶），不会尝试进行任何操作，凹槽内的物品实体也不会主动进入漏斗。

关闭的漏斗仍然可以：
* 被其他漏斗、投掷器和合成器向自身输出物品。
* 被下方的漏斗或漏斗矿车吸取自身的物品。

尽管不会进行任何操作，但与开启的漏斗类似，成功向关闭的漏斗输出物品后，该漏斗也会进入冷却时间。

# 你知道吗
* 漏斗在每个游戏刻都会尝试捕捉物品实体，这会造成持续的性能负载。
* * 通过在漏斗上方放置容器（如[投掷器](投掷器.md)和[堆肥桶](堆肥桶.md)）会阻止其检测物品实体，可略微减小漏斗带来的负载。
* * 通过激活漏斗使其关闭，可显著减少漏斗带来的负载。
* 尽管漏斗不能捕抓在其上方[碰撞箱](碰撞箱.md)完整的方块上方的物品，，仍然可以用[活塞](活塞.md)将物品推入方块内来拾取物品。
