# 物品格式

*页面ID: 150090* | *来源: Minecraft Wiki*

* *物品堆叠（Item Stack）**是游戏使用[物品](物品.md)的一种形式，其以统一的格式存储于各个游戏文件中。

# 数据格式
物品数据存在于游戏各处，例如生物[物品栏](物品栏.md)、[村民交易](村民交易.md)内容和[物品实体](物品实体.md)等实体数据，容器物品栏等方块实体的数据。

物品存储有两种方式：
* 带槽位存储：带有标签指定物品所在的槽位，比如在箱子中。
* 不带槽位存储：物品不在槽位中，而是作为某个属性类的数据或配置项，例如物品实体。

# 物品堆叠
物品堆叠为单纯的物品类型提供了附加的物品数据，包括物品堆叠数量、组件修订等。

当游戏需要使用物品的[数据组件](数据组件.md)数据时，会从两部分获取：一部分来源于物品的默认组件，另一部分来源于物品数据中的组件修订。游戏会在默认组件的基础上进行组件修订，得到实际使用的组件数据。显示的高级[提示框](提示框.md)中的组件数量即实际使用的组件数量。

# = 编码格式 =
游戏定义了多种不同的物品堆叠格式：

* 基础数据格式：必须指定物品ID，物品数量和组件修订可选。此格式是游戏使用最广泛的格式，上文的存储格式即使用此格式。
* 可选数据格式：物品堆叠可以为空，只用于[快捷栏](快捷栏.md)。
* 单一物品堆叠格式：必须指定物品ID，物品数量固定为1，组件修订可选。
* 带严格性验证的基础数据格式：在基础数据格式的基础上，物品堆叠需满足严格性验证。
* 带严格性验证的单一物品堆叠格式：在单一物品堆叠格式的基础上，物品堆叠需满足严格性验证。

* *严格性验证**

游戏会在部分场景下对物品进行进行严格性验证。严格性验证分为两步，依次进行，只要其中一个条件不满足则视为验证失败：

* 对物品堆叠组件的验证：
* * 若物品带有<code>max_damage</code>组件，则物品最大堆叠数不能大于1，否则验证失败。
* * 若物品带有<code>container</code>组件，则要求物品栏内每个物品都通过对物品堆叠数量的验证。
* * 若物品带有<code>bundle_contents</code>组件，则要求物品栏内每个物品都通过对物品堆叠数量的验证。
* * 若物品带有<code>charged_projectiles</code>组件，则要求物品栏内每个物品都通过对物品堆叠数量的验证。
* 对物品堆叠数量的验证：
* * 若物品堆叠的数量大于其最大堆叠数，则验证失败。

简而言之，严格性验证使得物品不能即可堆叠又可损坏，其堆叠数量也不能超出最大堆叠数。

游戏会在定义物品堆叠和对既有物品进行组件修订时（如和）进行严格性验证。此外，<code>container</code>、<code>bundle_contents</code>和<code>charged_projectiles</code>组件自身中的所有物品以及其他部分游戏场景使用的物品也会进行严格性验证。

如果严格性验证失败，则游戏会认为这是一个无效物品，对应的命令无法解析，对应的文件加载失败。

# = 物品默认组件 =
未经游戏外部途径修改而获取的物品均拥有默认组件。

在游戏内，物品默认组件可定义为：使用命令且不指定组件修订时所获取物品的组件。

物品默认组件不会序列化为物品数据，因此无法被获取，且当某组件值被设定为默认值时游戏也不会在物品数据中存储此组件。

物品默认组件与物品类型具有强关联性，物品的默认组件不会被其他物品继承。发生物品替换时，如果替换行为会保留原物品的物品堆叠组件，则只有被序列化为物品数据的组件修订会被结果物品继承。

[创造模式物品栏](创造模式物品栏.md)中，物品可能还有其他组件，这些组件依靠物品数据生效。当物品现有组件与创造模式物品栏给定组件完全一致时，该物品：
* [创造模式](创造模式.md)下，在物品提示框中以蓝色字显示其分类。
* 如果物品堆叠上限大于1，则可与创造模式物品栏给定物品堆叠。

物品至少拥有12个默认组件，不同物品的默认组件可能不同。
