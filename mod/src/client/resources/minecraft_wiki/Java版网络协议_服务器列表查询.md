服务器列表查询协议是Java版网络协议的一部分，此协议用于客户端在[服务器列表](服务器列表.md)屏幕中获取服务端信息与延迟。

# 协议内容
当客户端进入服务器列表屏幕，或者按下刷新按钮时，就会同时对所有服务端发起连接。

在连接的握手阶段时，客户端会发送意向数据包<code>intention</code>要求切换到服务器列表查询阶段。服务端接收到意向数据包后，如果<code>enableStatus</code>设置为<code>true</code>且服务端初始化完成，会立刻切换到服务器列表查询阶段。如果不满足上述条件，服务端将直接中止连接，客户端将无法获得服务端数据，并在日志中报错“”。

客户端在切换阶段后，立刻发送<code>status_request</code>C2S包，服务端接收后会发送<code>status_response</code>S2C包返回服务端的基础数据。<code>status_response</code>S2C包中仅包含一个字符串字段，内部为JSON数据，具有下列结构：

<div class="treeview">
*  JSON根标签
* * ：（默认为空字符串）服务器的MOTD（Message Of The Day）。原版服务端中此项只可能为字符串，但实际上客户端以[文本组件](文本组件.md)解析。
* * ：服务端的图标信息。此数据为Data URL<ref>https://developer.mozilla.org/zh-CN/docs/Web/URI/Reference/Schemes/data</ref>，以<code>data:image/png;base64,</code>作为前缀，后续为原始PNG图片的[Base64](wzh:Base64.md)编码字符串。图片必须为64&times;64像素，否则客户端将拒绝渲染。
* * ：（默认为<code>false</code>）服务端是否要求客户端必须建立安全的聊天信息交换协议。
* * ：服务端当前在线玩家信息。此字段不存在时，客户端将在应显示为玩家数量的组件上渲染灰色的“”。
* ** ：服务端最多可以容纳的玩家数量。
* ** ：当前在线玩家数。
* ** ：（默认为空列表）当前部分在线玩家的列表。如果[服务端配置文件](服务端配置文件格式.md)内设置<code>hide-online-players</code>为<samp>true</samp>，即使有玩家在线此列表也将为空。原版服务端默认最多随机挑选12个在线玩家信息。
* *** ：一个在线玩家信息。如果在线玩家禁止被列出（对应[客户端选项文件](客户端选项文件格式.md)中的<code>options.allowServerListing</code>），玩家名称会被匿名为“”（如果客户端版本低于[25w36a](25w36a.md)，则只会显示为<code>Anonymous Player</code><ref></ref>），UUID被匿名为全0UUID。
* **** ：玩家名称。
* **** ：带连字符的玩家[UUID](UUID.md)。
* * ：服务端版本信息。如果此字段不存在，客户端将显示版本名称为“”并认为此服务端的协议版本为0。
* ** ：版本名称。
* ** ：服务端的[协议版本](协议版本.md)。
</div>

如果服务端版本低于[23w07a](23w07a.md)，在服务端初始化过程中将允许客户端查询服务端状态数据，但服务端在初始化完毕后才会生成服务端状态数据。如果客户端对低于23w07a正在启动的服务端进行查询，服务端会返回空的服务端状态数据，使得客户端无法获取信息，从而在服务端列表中显示为“”。

客户端接收到<code>status_response</code>后，会立刻发送<code>ping_request</code>C2S包，服务端接收后立刻返回<code>pong_response</code>S2C包，客户端检测发出到接收两个数据包的时间计算出到服务端的延迟，并中止连接。此时整个查询流程结束。

上述所有流程可以总结如下：
# 客户端建立连接，发送意向数据包，切换阶段为服务器列表查询阶段。
# 服务端接收意向数据包，切换阶段为服务器列表查询阶段。
# 客户端发送<code>status_request</code>C2S包要求查询服务端状态。
# 服务端接收<code>status_request</code>，发送<code>status_response</code>S2C包。
# 客户端接收<code>status_response</code>，立刻发送<code>ping_request</code>C2S包。
# 服务端接收<code>ping_request</code>，立刻发送<code>pong_response</code>S2C包，中止连接。
# 客户端接收<code>pong_response</code>，中止连接。

服务端在部分情况下在发送<code>pong_response</code>S2C包前就已经中止连接，导致客户端无法接收到此数据包。此时客户端仍然认为查询流程正常结束，但不会获得延迟数据。

如果在查询流程中，服务端接收到了两次<code>status_request</code>C2S包，则会立刻中止连接。如果是客户端接收到两次<code>status_response</code>S2C包，客户端也会立刻中止连接，并认为查询流程出现错误，在日志中报错“”。

如果客户端发生查询流程错误，客户端都会在服务器列表屏幕显示此服务端。如果客户端不是因为无法连接到服务端发生错误，而是因为查询流程中发送的数据包无法对应产生错误，客户端会再次尝试使用旧版兼容服务器列表查询对服务端发起连接。

# 旧版兼容协议
为了对旧版服务器列表进行兼容，在当前版本的客户端和服务端仍然保持旧版兼容的服务器列表查询协议。

旧版兼容协议全部不使用当前的标准协议数据包结构，且使用此协议建立连接时必须保证第一个数据包就是旧版兼容数据包，否则后续服务端会将此数据包识别为错误。

当前版本的客户端在遇到无法正确解析的服务端查询协议时，会使用旧版兼容版本1协议，使用附带信息版本，以协议版本127发送到服务端重新查询数据，以获取旧版服务端的信息。当前版本的服务端如果检查到客户端使用旧版兼容协议连入，则会以协议版本127使用对应版本协议响应发送到客户端。

版本0协议是不高于[12w42a](12w42a.md)的版本使用的服务器列表查询协议。在连接建立后，客户端需要立刻发出一个字节<code>0xFE</code>，服务端在收到此字节后会切换到旧版兼容协议，并确认无后续数据后，向客户端发送下列负载：

数据字符串*Data*中包含3个数据，分别为服务端的MOTD、玩家数量和最大玩家数，这三个数据转换为字符串后按照顺序使用分节符<code>§</code>（U+00A7）拼接。

# = 版本1协议 =
版本1协议是[12w42b](12w42b.md)到[13w39b](13w39b.md)所有版本使用的服务器列表查询协议。版本1协议又分为两个版本：
* 无附带信息版本，用于12w42b到[1.6](Java版1.6.md)的版本。此版本协议需要客户端发送两个字节<code>FE 01</code>用于代表使用版本1协议。
* 有附带信息版本，用于[1.6.1](Java版1.6.1.md)到13w39b的版本。此版本协议需要客户端按照下列结构发送数据：

服务端接收到版本1协议负载后，无论是否带有附带信息，都会返回与版本0协议类似的结构数据。与版本0协议不同的仅有数据字符串*Data*的内容，在版本1中此项包含5个数据，分别为服务端协议版本、版本名称、MOTD、玩家数量和最大玩家数，各个数据转换为字符串后使用空字符（U+0000）分隔，并在头部添加三个字符<code>U+00A7 U+0031 U+0000</code>。

# 局域网发现协议
局域网发现协议是对于服务端开放局域网世界时使用的服务器列表查询协议。客户端可以在不知道服务端地址的情况下，使用此协议发现局域网中的局域网世界服务端并获取服务端信息。

局域网发现协议使用[UDP](wzh:UDP.md)协议，不属于常规网络协议的一部分。当服务端开放局域网世界时，每过1.5秒服务端就会向<code>224.0.2.60:4445</code>[多播](wzh:多播.md)发送一条以[UTF-8](wzh:UTF-8.md)编码的服务端信息字符串，格式为<code>-{}-[MOTD]<*服务端MOTD*>[/MOTD][AD]<*服务端端口*>[/AD]</code>。

客户端进入服务器列表屏幕，或者按下刷新按钮时，会开始监听<code>224.0.2.60:4445</code>上的数据报。当客户端接收到数据报时，就可以解析出服务端的IP地址，并从数据报内容中提取出服务端信息字符串，获得服务端MOTD和端口信息。如果服务端信息字符串不标准，客户端允许MOTD无法正确读取，但端口要求必须可以正确读取。如果MOTD不能正常读取，客户端会将MOTD识别为<code>missing no</code>。如果在服务端信息字符串前后有多余字符，客户端将忽略这些字符进行正确解析。
