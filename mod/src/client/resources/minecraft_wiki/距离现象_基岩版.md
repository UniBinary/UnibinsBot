# 距离现象/基岩版

*页面ID: 54570* | *来源: Minecraft Wiki*

当[玩家](玩家.md)远离[世界](世界.md)原点时，世界会逐渐变得异常。这主要是由于用于定位的[32位浮点数](wzh:单精度浮点数.md)存在精度损失，仅给小数分配了23位的空间。

# 总体现象
某些现象可能在任何距离发生，它们随着[坐标](坐标.md)的增加会逐渐恶化。游戏在许多计算中使用32位浮点数，例如玩家的位置。32位浮点使用其中23位来实现精度（其他9位用于符号和数量级），因此对于任何给定的数量级，都有2<sup>23</sup>个（8,388,608）可能的位置。例如，在1和2之间有8,388,608个可能的位置，每个位置相距格，但在8,388,608和16,777,216之间也有8,388,608个可能的位置，每个位置相隔一格。通常，在2<sup>n</sup>和2<sup>n+1</sup>之间，有效位置相距2<sup>n-23</sup>。在较高的坐标下，有效位置相距更远，因此位置不太精确。这一原则有几个含义。

# = [方块](方块.md)渲染错误 =
很多方块被渲染为[不完整方块](不完整方块.md)，而游戏使用32位浮点数来计算方块角的位置。在高坐标下，这些坐标会发生偏移，导致方块渲染不正确：具有更精细模型的方块（例如：[仙人掌](仙人掌.md)，各种火把）通常在较低的坐标处就会出现故障（少数方块在相对较低的X/Z ±131,072处就出现错误的渲染），而[完整方块](完整方块.md)在X/Z ±16,777,216以前仍然能够正确渲染，比大多数不完整方块更远。

# = [地形](地形.md)生成错误 =
在[1.18.0](基岩版1.18.0.md)以后，在坐标X/Z =±2,812,332左右，许多[山地](山地.md)类生物群系就逐渐不再生成，取而代之的是[熔岩湖](熔岩湖.md)。[远古城市](远古城市.md)也会露出地面。

当坐标X/Z>±67,108,864时，地形会被拉伸，并且每经过2的次幂，拉伸的长度都会翻倍。在实际游戏中，由于条纹之地的存在，玩家仅能通过[地图](地图.md)看到这种地形。

在Windows平台上，[末地](末地.md)的地形生成会在X >±9,991,500左右（具体的起始位置随种子有微小变化）时出现故障，外岛将会被填充为几乎实心。填充的地形在延伸约9,991,500格后恢复正常，并在约 9,991,500格后复现，共重复三次，最后一次恢复正常的位置约为X=±59,949,000。当 X/Z>约±62,000,000时，正常地形也不再生成。只有小型岛屿仍会生成。但在实际游戏中，玩家仅能通过[地图](地图.md)看到这些变化。

# = 无法缓慢[移动](移动.md) =
游戏中的[实体](实体.md)每一[游戏刻](游戏刻.md)可以移动一次。在移动实体时，游戏会在实体原坐标的基础上沿三个坐标轴分别增加该坐标轴上的速度分量值（单位为方块每刻）。由于32位浮点数运算误差，移动后的坐标会被四舍五入到最近的有效位置。如果实体的移动速度过小或坐标过大，在四舍五入到最近的有效位置时实体会保持在原来的位置，导致实体无法移动。

更具体地说，在2<sup>n</sup>和2<sup>n+1</sup>之间，一个实体的速度会被四舍五入到（20×2<sup>n-23</sup>）方块/秒的最接近倍数，因此它必须每秒移动至少（10×2<sup>n-23</sup>）格才能被视为实际移动。即使实体可以实际移动，由于速度已被舍入的原因，实体在特定坐标范围的实际移动速度可能会比坐标原点处偏大或偏小。

有几种方法可以减缓玩家的移动，如[潜行](潜行.md)、状态效果、使用物品（如向后拉[弓](弓.md)）或借助某些方块（如[蜘蛛网](蜘蛛网.md)和[灵魂沙](灵魂沙.md)）。此外，沿着对角线移动会降低玩家在任何给定轴上的速度。这种效果可以通过几乎（但不完全）沿着一个轴移动来放大，通过在另一个轴上用方块阻挡并移动，玩家可以在不改变其在另一个轴上的坐标的情况下做到这一点。

# = 抖动 =
游戏通常以每秒60帧的速度运行，因此当玩家移动时，游戏必须计算出相机在刻度之间的中间帧上的位置。这通常不会出现问题，但如果玩家以尽可能慢的速度移动，中间帧上的相机位置就会失真，游戏就会开始抖动。

最终，缓慢的速度和精度误差达到了玩家每游戏刻只前进1个有效位置的程度，迫使中间帧恰好呈现在起始或结束位置。因此，摄像机的移动就好像游戏是以每秒20帧而不是60帧的速度进行的。

由于较慢的速度在较低的坐标下就会变得抖动，因此**无法准确说出**开始出现抖动的具体坐标。

# = 沿方块边缘掉出世界 =
在极端坐标下，较小实体的[碰撞箱](碰撞箱.md)宽度会变成0，它们一般会从方块的边缘掉出世界。例如，如果宽度小于格的实体坐标超过X/Z ±2,097,152，则其碰撞箱角的位置会被四舍五入到最近的有效位置，由于其碰撞箱在每个方向上从其中心坐标延伸不到格，因此碰撞箱的两侧都被舍入到相同的位置，因此表观碰撞箱宽度为0。

此外，还可以控制碰撞箱的大小并在低得多的坐标下穿越世界。实体中心的位置存储在NBT中，而单个碰撞箱角的位置存储于内存中。如果玩家正在穿过2的整数次幂坐标，这些角可能会分别以不同的速度移动，导致碰撞箱的宽度被改变。在某些情况下（比如重载世界、使用命令、[末影珍珠](末影珍珠.md)或[紫颂果](紫颂果.md)传送、骑乘实体、[潜行](潜行.md)、[爬行](爬行.md)、[游泳](游泳.md)、使用[鞘翅](鞘翅.md)滑翔、使用有[激流](激流.md)魔咒的[三叉戟](三叉戟.md)冲刺）会使碰撞箱大小重置为0.6。玩家的碰撞箱宽度有可能会变成0，导致玩家穿过方块边缘掉入虚空<ref></ref>。相反，玩家的碰撞箱也可以被扩大到几个方块宽。

# = 低度故障区（X/Z ±131,072~1,048,575） =
在这里，一些正常的运动开始出现故障，且有些精细的方块模型开始出现渲染错误。

# = 中度故障区（X/Z ±1,048,576~16,777,215） =
方块模型渲染的位置基于它的角的位置（坐标也是32位浮点数），常规情况下是的倍数。只要浮点数能够精确到最接近的十六分之一，大多数方块都会正常渲染。在X/Z ±1,048,576（2<sup>20</sup>）之后无法达到这个精度，因此方块将无法正常渲染。<ref></ref>

在RTX版本中，光线的渲染不会受到浮点精度的影响，虽然方块模型的渲染依旧会出现问题。<ref></ref>

另外，大多数“通常”的移动方式在这之后将无法移动。

# 垂直方向极限
类似于X轴和Z轴，游戏也会在Y坐标超过某一位置时出现错误。由于方块无法放置在Y>319（[主世界](主世界.md)）或Y>127（[下界](下界.md)）或Y>255（[末地](末地.md)）的地方，所以不会出现方块渲染故障，但会出现其他现象。

这些影响也会在负坐标产生，但在Y=-105（主世界）或Y=-41（下界、末地）的地方有一处障碍。可以通过传送至X/Z ±8,388,608处规避这一限制，或传送到Y=-105（主世界）或Y=-41（下界、末地）以下。

# 条纹之地
[缩略图|位于坐标X/Z 16,777,216处的“条纹之地”](File:Stripe Lands.jpg.md)

条纹之地是由游戏渲染与碰撞箱计算产生的现象，而不是与地形生成直接相关的现象。<ref></ref><ref name="StripeLands"></ref>条纹之地作为渲染错误起始于X/Z ±16,777,216。它之所以存在，是因为坐标偏离了整整一格，导致方块本身（而不止其边角）出现在错误的位置。

坐标超过X/Z ±33,554,432后，所有方块均呈现为二维，并且有效位置之间的间隙加倍至格。坐标每到2的整数次幂，该间隙的宽度都会再次加倍，并且在X/Z ±1,073,741,824处达到128个方块宽。这是方块间的最大距离，因为游戏会在X/Z ±2,147,483,648附近崩溃。
