# 基岩版1.19.10.22

*页面ID: 96665* | *来源: Minecraft Wiki*

<onlyinclude>

* *beta 1.19.10.22**（Android）、**Preview 1.19.10.22**（iOS/iPadOS/Xbox/Windows）是[基岩版1.19.10](基岩版1.19.10.md)的第3个测试版，发布于2022年6月8日<ref></ref>，加入了[悦灵](悦灵.md)的人为生成方式，同步了更多的特性，并修复了一些漏洞。

# 更改
# = 方块 =
* *[盛开的杜鹃树叶](盛开的杜鹃树叶.md)**
* 英文名称由“Flowered Azalea Leaves”重命名为“Flowering Azalea Leaves”以匹配。

* *[青金石块](青金石块.md)**
* 英文名称重命名为“Block of Lapis Lazuli”以匹配。

# = 物品 =
* *[山羊角](山羊角.md)**
* 更改了“Feel”音效以匹配。
* 将“Resist”音效重命名为“Dream”以匹配。

# = 生物 =
* *[悦灵](悦灵.md)**
* 现在会在[唱片机](唱片机.md)播放音乐时跳舞。
* * 当唱片机停止播放音乐或距离唱片机过远时，悦灵会停止跳舞。
* * 当跳舞中的悦灵获得[紫水晶碎片](紫水晶碎片.md)时，其所在的位置会生成另一只悦灵，并发出爱心粒子和紫水晶音效。
* ** 生成后，双方会有2.5分钟的冷却时间。

# = 常规 =
* *[控制](控制.md)**
* 更新了“十字准星”触摸控制方案下的操作按钮。

# 实验性
本段落的内容需要开启[实验性玩法](实验性玩法.md)中的“旁观模式”和“假日创造者功能”子选项后才可使用。

# = 常规 =
* *[旁观模式](旁观模式.md)**
* 在旁观模式中，其他区块上的活动对象不再会被剔除掉。

# = 技术性 =
* *常规**
* 将组件重命名为。
* 将组件的字段重命名为。
* 将组件的字段重命名为。

* *性能与稳定性**
* 降低了世界开启“假日创造者功能”选项后的加载时间。

# 修复
* *原版趋同**
* 盛开的杜鹃树叶的英文名称由“Flowered Azalea Leaves”重命名为“Flowering Azalea Leaves”。
* 现在山羊角拥有与Java版中的“Call”音效相同的变种。（）
* 山羊角最后一个音效的名称由“Resist”重命名为“Dream”以匹配Java版。（）

* *悦灵**
* 悦灵现在能够跟随主人进入下界传送门。（）

* *深暗之域**
* 依附于幽匿感测体的紫水晶簇不再会被摧毁。

* *幽匿尖啸体**
* 现在幽匿尖啸体的粒子会在后面正确渲染。（）

* *幽匿催发体**
* 现在当生物在多个幽匿催发体的作用范围内死亡时，只有最近的一个会因此激活。
* 不掉落经验的生物在幽匿催发体附近死亡而激活幽匿催发体时，成就“蔓延”不再会被解锁。

* *监守者**
* 监守者钻地时不再会出现错误纹理或掘地粒子效果。（）

* *青蛙**
* 青蛙不再会在较浅的水流中产下青蛙卵。（）

* *游戏内容**
* 修复了生物进入下界传送门后会消失不见的问题。（）
* 抗性提升效果不再比应有效果等级低一级。（）
* 急迫效果I现在会正确提高玩家的挖掘速度。（）
* 潮涌能量I现在会给予急迫I而不是急迫II。
* 现在载具坐满乘客时，移动设备玩家可以不潜行而直接打开容器实体（如运输船）。

* *方块**
* 现在青金石块的英文名称为“Block of Lapis Lazuli”。（）
* 现在切制铜台阶及其变种可以第一次放置在相同方块的顶部。（）

* *命令**
* 现在使用命令生成的掠夺者队长或卫道士队长又会默认处于敌对状态了。（）

* *常规**
* 现在加载带有中的字段，字段，以及中的字段的无效类别值时，相关内容日志错误会确保不被忽略。（)
* 修复了被默认给予操作员权限的玩家不能执行操作员命令的问题。
* 修复了设置为默认给予新玩家操作员权限的世界只会给予成员权限的问题。

* *图形**
* 始于负数迷雾的迷雾设置不再会使UI中的玩家模型染上迷雾颜色。
* 材质不再会被RenderDragon剔除。

* *物品**
* 修复了发射器发射的雕刻南瓜不会正确装备到附近生物的盔甲槽中的问题。

* *生物**
* 鹦鹉现在又会因为喂食曲奇而中-{}-毒。（）

* *玩家**
* 玩家按住跳跃键上船后不再会不停地跳跃。（）

* *性能与稳定性**
* 修复了生物具有组件时可能发生的崩溃。

* *技术性**
* 修复了带有偏移量的弹射物不会根据玩家的旋转方向来生成的问题。（）
* 现在蛋糕被吃掉一片时会发送游戏事件。
* 现在饥饿值消耗组件使用新的正确默认值。（）
* * 若有需要，修改了的附加包可能需要重新设置饱和度以与默认值相匹配。</onlyinclude>
