# 数据生成器

*页面ID: 148404* | *来源: Minecraft Wiki*

* *数据生成器（Data Generator）**是导出游戏数据驱动文件和转换数据的工具程序。

# 文件结构
数据生成器位于[客户端核心文件](客户端核心文件.md)和[服务端核心文件](服务端核心文件.md)内，作为可运行主类存在于两种文件的代码中。

数据生成器分为两种：服务端数据生成器和客户端数据生成器。
* 服务端数据生成器在客户端和服务端核心文件中都存在，类名为<code>net.minecraft.data.Main</code>。
* 客户端数据生成器只存在于客户端核心文件中，类名为<code>net.minecraft.client.data.Main</code>。

# 启动参数
因为核心文件清单文件中定义的主类并非数据生成器类，所以必须指定JVM参数运行数据生成器。

如果要运行服务端数据生成器，需要下列命令：

<syntaxhighlight lang="bash">
java -cp "...;client.jar" net.minecraft.data.Main <启动参数>               # 客户端核心文件运行方式（省略号代表需要额外指定类路径，参见 <版本号>.json 中的"libraries"字段）
java -DbundlerMainClass=net.minecraft.data.Main -jar server.jar <启动参数> # 服务端核心文件运行方式
</syntaxhighlight>

如果要运行客户端数据生成器，需要下列命令：

<syntaxhighlight lang="bash">
java -cp "...;client.jar" net.minecraft.client.data.Main <启动参数> # 需要额外指定类路径
</syntaxhighlight>

下列为服务端数据生成器启动参数：
* <code>--help</code>：输出服务端数据生成器命令帮助。此参数具有最高优先级，其他参数会被此项参数忽略。
* <code>--dev</code>：提供NBT转换SNBT工具程序。
* <code>--reports</code>：提供生成报告工具程序。
* <code>--server</code>：提供SNBT转换NBT工具程序和服务端数据包导出工具程序。
* <code>--all</code>：包含上述3个工具程序，即<code>--dev --reports --server</code>三个参数的简写。
* <code>--input <*文件或目录*></code>：指定SNBT或NBT输入，此参数可以多次出现。
* <code>--output <*目录*></code>：指定生成数据保存的目录。默认为。
* <code>--validate</code>：没有实际作用，本质是为了检测启动参数的有效性。

下列为客户端数据生成器启动参数：
* <code>--help</code>：输出服务端数据生成器命令帮助。此参数具有最高优先级，其他参数会被此项参数忽略。
* <code>--client</code>：提供客户端资源包导出工具程序。
* <code>--all</code>：与<code>--client</code>等价。
* <code>--output <*目录*></code>：指定生成数据保存的目录。默认为。

# 导出数据
根据启动参数的不同，数据生成器会提供指定的工具程序并生成对应的数据。

# = NBT-SNBT转换工具 =
使用<code>--dev</code>启动参数并指定<code>--input</code>可以使数据生成器输出NBT文件的对应的SNBT格式。

数据生成器只会识别后缀名为的文件进行SNBT转换，其他文件则被忽略。在输出文件时，游戏会保持原文件的相对目录路径进行输出。

数据生成器只能转换以GZip压缩的NBT文件。如果文件无效，程序将在日志中输出错误信息，但不会中止程序，而是跳过此文件。

特别地，如果该NBT文件是结构存储文件，则输出SNBT与原始NBT有差异，详见[结构存储格式#SNBT格式](结构存储格式#SNBT格式.md)。

# = SNBT-NBT转换工具 =
使用<code>--server</code>启动参数并指定<code>--input</code>可以使数据生成器输出SNBT文件的对应的NBT格式。

数据生成器只会识别后缀名为的文件进行NBT转换，其他文件则被忽略。在输出文件时，游戏会保持原文件的相对目录路径进行输出。

对于所有被数据生成器识别的SNBT文件，如果文件无效，程序将在日志中输出错误信息，但不会中止程序，而是跳过此文件。

特别地，由结构存储文件输出的SNBT会被转回原始形式。

# = 服务端数据包导出工具 =
使用<code>--server</code>启动参数时数据生成器将自动导出服务端数据包。此工具与SNBT-NBT转换工具使用同一个启动参数，所以在SNBT-NBT转换工具启动的同时也会导出服务端数据包。

导出服务端数据包时，数据生成器会在输出目录中按照数据包的目录格式进行输出。数据生成器不会输出所有数据包内数据，只会输出下列数据：
* 所有可写注册表的注册项数据（如世界生成、变种等注册表）。
* 进度（）。
* 战利品表（）。
* 配方（）。
* 部分注册表标签数据，包括：方块、物品、生物群系、旗帜图案、生成结构、伤害类型、实体类型、超平坦世界预设、流体、游戏事件、山羊角乐器、画变种、兴趣点、世界预设、魔咒、对话框、时间线、药水效果、村民交易。

同时，游戏也会输出内置数据包的数据，这些内置数据包会被放置在下，其内部结构与上文所述类似，但具体信息由具体的数据包定义，因此可能不包含上述绝大多数信息。

# = 客户端资源包导出工具 =
对于客户端数据生成器，使用<code>--client</code>启动参数时数据生成器将自动导出客户端资源包数据。

导出客户端资源包时，数据生成器会在输出目录中按照资源包的目录格式进行输出。数据生成器只会生成下列资源包数据：
* 纹理图集。
* 装备模型。
* 方块状态映射.
* 物品模型映射。
* 物品模型、方块模型。
* 路径点样式。

# == 方块报告 ==
方块报告位于，包含了方块状态相关数据。具有下列JSON结构：

<div class="treeview">

* *** ：一项方块状态。

# == 注册表组件报告 ==

注册表组件报告位于目录内，假设某元素以命名空间ID<code><*N*>:<*I*></code>注册到了数据包路径为<code><*P*></code>的注册表中，则此报告工具会将它生成到中。每个文件都具有下列JSON结构：

<div class="treeview">
*  JSON文件根对象
* * ：此注册项的默认组件信息。
* ** ：此注册项具有的一项组件及其信息。
* ** ：此注册项不具有的一项组件及其信息。
</div>

此报告工具不会生成进度、配方、战利品表、物品修饰器和谓词的默认组件。在原版游戏中，只有物品注册了默认组件，因而事实上此工具只会为物品生成对应的默认[数据组件](数据组件.md)信息，其他文件内只有一个内容为空的。
