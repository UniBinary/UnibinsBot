# 版本格式

*页面ID: 48157* | *来源: Minecraft Wiki*

每个Minecraft的版本和开发阶段都使用了不同的版本系统。

# Java版
# = pre-Classic =
在[pre-Classic](Java版pre-Classic.md)期间，游戏版本没有被编号，而是使用一个游戏缩写后接发布日期的时间：日、小时和分钟。例如，[rd-160052](rd-160052.md)发布于**瑞典当地时间**5月**16**日的**00**:**52**（12时52分）。临时名称*[RubyDung](RubyDung.md)*——一个[Notch](Notch.md)之前开发的游戏（缩写为**rd**）——被用作版本号的开头部分，后来更改为**mc**。

# = Classic =
在[mc-161648](mc-161648.md)期间，用户fartron请求Notch添加构建计数，<ref></ref>这项功能在下一个版本[0.0.2a](Java版Classic 0.0.2a.md)中加入了。这标志着[Classic](Java版Classic.md)阶段的开始。在此阶段，版本号使用三个数字后接“a”表示，漏洞修复补丁则采用下划线加修订号的格式。例如，[0.0.18a_02](Java版Classic 0.0.18a_02.md)是[0.0.18a](Java版Classic 0.0.18a.md)的第二个补丁。“a”代表“**a**lpha”，这是该开发阶段的原始名称。<ref></ref>在版本[0.0.23a_01](Java版Classic 0.0.23a_01.md)期间，Notch宣布将修改版本控制系统，移除其中一个0和“a”。<ref></ref>这个时期恰好处于[生存测试](生存测试.md)的开发阶段，因此版本号添加了“SURVIVAL TEST”后缀，有时包含下划线，如[0.24_SURVIVAL_TEST](Java版Classic 0.24_SURVIVAL_TEST.md)所示。在[0.27 SURVIVAL TEST](Java版Classic 0.27 SURVIVAL TEST.md)之后，生存测试阶段结束，版本格式简化为两个数字（第一个是0）和一个可选的下划线漏洞修复补丁，如[0.28_01](Java版Classic 0.28_01.md)。

# = Indev和Infdev =
在[Indev阶段](Java版Indev.md)早期，Classic阶段后期的命名规则继续被使用，许多版本的版本号[停留在了0.31](Java版Indev 0.31.md)。在Indev的开发过程中，Notch将版本号从“0.31”改为“[Minecraft Indev](Minecraft Indev.md)”，其中“Indev”是“**in** **dev**elopment”（开发中）的合成词。当[Infdev](Java版Infdev.md)开始后，版本号又改为“[Minecraft In**f**dev](Minecraft Infdev.md)”，其中“Infdev”是“**inf**inite **dev**elopment”（无限开发）的合成词，因为Notch加入了无限世界生成功能。

由于此阶段所有版本的版本号相同，因此在[启动器](启动器.md)中将单个Indev和Infdev版本根据发布日期再编号。例如，2010年1月10日发布的Indev 0.31版本被命名为[Indev 0.31 20100110](Java版Indev 0.31 20100110.md)。若在同一天发布多个版本，则在日期后添加发布的UTC时间。例如，2009年12月23日14:57（UTC）发布的Indev 0.31版本被命名为[Indev 0.31 20091223-1457](Java版Indev 0.31 20091223-1457.md)。

# = Alpha =
自[Alpha v1.0.1](Java版Alpha v1.0.1.md)起，[Alpha](Java版Alpha.md)期间的版本重新将版本号加入游戏。此时期版本号格式为“v”后接三个数字，分别表示阶段（phase）、主版本号（major）和次版本号（minor）。此时Minecraft已结束Indev和Infdev的“开发”阶段标签，因此阶段数字被设为“1”。开发阶段中可使用下划线标注漏洞修复格式。例如，[Alpha v1.2.3_02](Java版Alpha v1.2.3_02.md)是Alpha阶段第2个主版本（即“.2”）的第3个次版本（即“.3”）的第2个漏洞修复（“_02”）版本。

# = Beta =
在[Alpha v1.2.6](Java版Alpha v1.2.6.md)后，[Beta](Java版Beta.md)阶段的版本号被重置为1.0。Beta期间的版本号包含两个数字，并可使用下划线标注漏洞修复补丁。例如，[Beta 1.1_01](Java版Beta 1.1_01.md)修复了[Beta 1.1](Java版Beta 1.1.md)的漏洞。这一格式在Beta开发后期出现不一致：[Beta 1.7](Java版Beta 1.7.md)的下一个版本为[Beta 1.7_01](Java版Beta 1.7_01.md)，随后是[Beta 1.7.2](Java版Beta 1.7.2.md)。

# = 正式版 =
[Java版](Java版.md)正式发布时将版本号重置为[Java版1.0.0](Java版1.0.0.md)，此时的版本格式为<code>-{}-1.<主要版本号>.<次要版本号></code>，主要版本号和次要版本号均采用递增的方式，在[Java版1.21.1](Java版1.21.1.md)之前，主要版本号代表着更新主题，次要版本号仅用于次要更新，通常用于修复漏洞和稳定性改进，少数次要版本会更新新的游戏内容；自[Java版1.20.5](Java版1.20.5.md)开始，一些次要版本也会用于发布主题更新，例如[1.21.4](Java版1.21.4.md)。1.0.0是唯一保留末尾“.0”的主版本（后续版本均省略该格式，例如[Java版1.1](Java版1.1.md)）。[25w45a](25w45a.md)至[1.21.11](Java版1.21.11.md)发布的未混淆版本会在常规版本名后添加“Unobfuscated”。

2025年12月2日，Mojang称为使命名符合新的更新策略，2026年起，新的版本格式调整为由年份、小更新发布序号及热修复发布序号组成，格式为<code>YY.D.H</code><ref name="new_version_numbering"></ref><ref></ref>，其中YY为两位年份，D为当年正式更新序号，H为热修复版本。

# == 快照（Snapshot） ==
从[1.1](Java版1.1.md)开始，每周快照的版本格式为“*YY*w*WWn*”：其中“*YY*”表示两位数的年份，“w”代表工作周期，“*WW*”为两位数的一年内周数，“*n*”为字母标识符（从“a”开始，依次为“b”、“c”等），代表当周内快照的发布顺序。歷來最高字母为“e”，以此命名的快照包括[12w30e](12w30e.md)、[13w47e](13w47e.md)和[15w35e](15w35e.md)。除[愚人节玩笑](彩蛋#愚人节.md)快照外，唯一未遵循此格式的是[13w12~](13w12~.md)。

2026年起，新的版本格式會由正式版版本号与快照发布顺序组成，版本号格式为“*正式版版本号*-snapshot-*x*”，版本名同理。例如，正式版“[26.1](Java版26.1.md)”的第一个快照的版本号为“[26.1-snapshot-1](Java版26.1-snapshot-1.md)”，版本名为“26.1 Snapshot 1”。

# == 预发布版（Pre-release） ==
Beta阶段就已发布以“预发布版”形式存在的预览版本，它们被视为最早的预发布版。其格式为“*版本数字* Pre-release *x*”，其中*x*为空或一个指定的修订版本号。在[1.0.0](Java版1.0.0.md)（当时称为Beta 1.9）的预发布版中，移除了“Pre-release”中的短横线（例如：[Beta 1.9 Prerelease 3](Java版Beta 1.9-pre3.md)）。

在[1.7.4](Java版1.7.4.md)之前，预发布版以正式版格式发布并采用递增版本号的方式（例如[1.4](Java版1.4.md)和[1.4.1](Java版1.4.1.md)实际上是[1.4.2](Java版1.4.2.md)的预发布版）。从[1.7.6](Java版1.7.6.md)到[1.13.2](Java版1.13.2.md)期间，预发布版采用“*版本数字*-pre*x*”格式，其中*x*代表修订版本号（例如[1.12-pre2](Java版1.12-pre2.md)）。目前最高數字為「10」（[1.13-pre10](1.13-pre10.md)）。

[1.14](Java版1.14.md)后版本名开始使用“*版本数字* Pre-Release *x*”格式（例如[1.14.1 Pre-Release 2](Java版1.14.1-pre2.md)）。[1.15](Java版1.15.md)起改为“*版本数字* Pre-release *x*”格式（如[1.15 Pre-release 1](Java版1.15-pre1.md)），但[1.15 Pre-Release 2](Java版1.15-pre2.md)和[1.15.2 Pre-Release 1](Java版1.15.2-pre1.md)例外。[1.20.2-pre3](Java版1.20.2-pre3.md)起重新采用1.14时期格式（[1.21.5 Pre-release 2](Java版1.21.5-pre2.md)例外）。

2026年起，新的版本格式会由正式版版本号与预发布版发布顺序组成，版本号格式为“*正式版版本号*-pre-*x*”，版本名未作修改。例如，正式版“26.1”的第一个预发布版的版本号为“26.1-pre-1”。<!-- 需要链接 -->

# == 发布候选（Release Candidate） ==
在[正式版1.0.0](Java版1.0.0.md)发布前，曾发布过两个属于该版本的发布候选版本。这两个版本（[RC1](Java版1.0.0-rc1.md)和[RC2](Java版1.0.0-rc2.md)）采用“RC*x*”格式命名。此后很长一段时间未再发布发布候选版本。

自[1.16 Release Candidate 1](Java版1.16-rc1.md)起，发布候选版本被重新引入。若发布候选版本未发现严重漏洞，其更新内容将直接应用于后续正式版。<ref></ref>其版本号命名格式为“*版本数字*-rc*x*”，对应的版本名则为“*版本数字* Release Candidate *x*”，其中*x*代表修订版本号。

2026年起，新的版本格式会由正式版版本号与发布候选顺序组成，版本号格式为“*正式版版本号*-rc-*x*”，版本名未作修改。例如，正式版“26.1”的第一个发布候选的版本号为“26.1-rc-1”。<!-- 需要链接 -->

# == 实验性快照（Experimental Snapshot） ==
[1.18 Experimental Snapshot 1](Java版1.18-exp1.md)首次引入实验性快照机制，用于在常规快照发布前进行早期功能测试。此类快照作为独立下载包分发，不纳入启动器版本列表，且无法加载其他版本创建的世界。其标准命名格式为“*版本数字* experimental snapshot *x*”，其中*x*代表修订号（例如[1.18 experimental snapshot 2](Java版1.18-exp2.md)）。但[1.18 Experimental Snapshot 1](Java版1.18-exp1.md)和[Deep Dark Experimental Snapshot 1](Java版1.19-exp1.md)例外，其名称中所有单词首字母均大写。

# 基岩版
# = Alpha =
当[携带版](携带版.md)最初发布时，版本格式遵循了一个“v”后面跟随三个数字——阶段号（phase）、主版本号（major）以及次版本号（minor）的格式。在开头则有“alpha”的字样。整个Alpha阶段的阶段号都是0，而当每一个版本发布时主版本号和小版本号都将相应增长（当主版本号增加时，次版本号总会被重置为0）。

这时的开发版均遵循在其父版本号后加上“build”及更新次数的格式。例如，[v0.14.0 alpha build 1](携带版0.14.0.b1.md)是Alpha版本[0.14.0](携带版0.14.0.md)的第一个开发版。

# = 正式版（携带版） =
正式版延续了Alpha版本的版本格式，但阶段号变成了1。

# == 开发版（携带版） ==
当时开发版还以“alpha”命名（不要和“Alpha”开发阶段相混淆），并且“alpha”的词语被放在一组四个数字版本号前（major.minor.patch.revision<ref>如<samp>[options.txt](options.txt.md)</samp>中所述</ref>）。前三个数字为父版本号（如[alpha 1.0.0.1](携带版1.0.0.1.md)是[1.0.0](携带版1.0.0.md)的开发版），第四个数字是内部版本号，未必每次发布都以1递增。

# = 正式版（基岩版） =
在[1.2.0](基岩版1.2.0.md)，“携带版”的名称被停用，并改为“基岩版”，不过基本的版本格式并无变化。

从[1.14.20](基岩版1.14.20.md)开始，基岩版的次要版本号开始使用两位以上数字，最后一位数字专门用于热修复或平台特定的错误修复。

从[1.16.0](基岩版1.16.0.md)开始，基岩版的主要版本号与Java版一致。

2026年起，将使用新版版本号的命名规则<ref name="new_version_numbering"></ref>，格式为<code>YY.DP</code>，其中YY为两位年份，D为当年正式更新序号，P为热修复序号。以2025年发布的第7次正式更新版本[群骑纷争](群骑纷争.md)正式版[基岩版1.21.130](基岩版1.21.130.md)为例，以新的版本号系统会被编号为“25.70”。

# == 开发版（基岩版） ==
开发版的前缀从携带版的“alpha”变成了基岩版的“beta”；不过基本的版本格式并无变化（如[beta 1.8.0.8](基岩版1.8.0.8.md)是[1.8.0](基岩版1.8.0.md)的开发版）。

从2022年1月起，在[Minecraft Preview](Minecraft Preview.md)的版本中，开发版被称呼为“Preview”，如[Preview 1.20.20.20](基岩版1.20.20.20.md)。

2026年起，开发版的命名规则格式为<code>YY.DP.BB</code>，其中YY为两位年份，D为当年正式更新序号，P为热修复序号，BB为开发版本序号。以[基岩版1.21.120.25](基岩版1.21.120.25.md)为例，以新的版本号系统会被编号为“25.60.25”。

# 原主机版
不同平台上的原主机版使用不同的版本格式。

[Xbox 360版](Xbox 360版.md)使用“Title Update（标题更新）”+字母“TU”和其后面的一个数字。

[Xbox One版](Xbox One版.md)的版本号格式和Xbox 360版基本相同，但用表示“Content Update（内容更新）”的“CU”代替了“TU”。

PlayStation上的版本使用一个一位数与一个两位数的组合作为版本号 （一个整数放在一个范围为00~99的整数前，以此理论，1.99以后应该是2.00——事实上PlayStation 4的基岩版内部版本号的确遵循了这一规则），有时也可能会跳过一部分版本号。

[Wii U版](Wii U版.md)的更新被称为“Patch”，版本号为“Patch”后加数字。

[Nintendo Switch版](Nintendo Switch版.md)则从1.0.1开始使用完整的三个数字作为版本号，但更新时仅有最后一个数字变化。
