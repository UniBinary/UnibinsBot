# 崩溃

*页面ID: 8818* | *来源: Minecraft Wiki*

<!-- 在Java版1.21.11-pre2测试：内存不足时不会弹出界面 -->

* *崩溃（Crash）**指[Minecraft](Minecraft.md)的非正常关闭。Minecraft发生崩溃时会立即关闭，也可能会显示一个[错误报告](崩溃报告文件.md)以标示崩溃原因。游戏时发生服务器崩溃，则会先保存世界再关闭游戏。

# 崩溃的原因
造成崩溃的最常见原因是[Mod](Mod.md)、漏洞与更新。

崩溃可能导致存档损坏。因此，强烈建议玩家定期备份存档，以减少崩溃造成存档损坏的损失。

# = Mod =

崩溃可能因[Mod](Mod.md)的冲突而发生。

可按以下步骤排查：
# 重命名在文件夹中的文件夹，然后启动Minecraft，Minecraft会创建一个新的文件夹。
# 确认游戏没有崩溃后，逐个安装Mod，每装一个就启动Minecraft并确认是否崩溃。
# 若崩溃再次发生，最后安装的Mod很可能是问题的根源，或它和别的Mod冲突。尝试移除该Mod，或重新排查其他Mod。

有些Mod需要多个组件一起安装才能正常运行。注意，有一些Mod不应安装在文件夹下，否则会导致崩溃。

# = 硬件问题 =
硬件问题也很容易引起崩溃或出错。如果是这样，其他应用很可能也会遇到问题。如果Minecraft是唯一遇到问题的游戏，那么不太可能是硬件问题。

如确实在其他游戏中遇到崩溃或出错现象，

崩溃可能与设备过热相关，请做以下检查：

* 检查设备的通风口是否被堵塞（被动散热设备除外）。堵塞在平时可能不足引起问题，但在较高负载（如玩游戏）期间，可能导致设备过热。
* * 如果使用的是笔记本电脑，确保两侧或底部的通风孔没有被阻塞。
* * 如果是主机，检查风扇位置有无堵塞，并查看内部情况。如有大量的灰尘，或某个风扇不旋转，应维修设备。
* 如无与过热相关的问题，崩溃的另一个原因可能是部件损坏，尤其是内存或显卡问题。如果问题最近开始出现，而没有安装任何更新或软件（如反病毒套件），可自己使用工具进行测试，或考虑维修设备。

应注意，即使设备符合Minecraft的基本系统要求，硬件也可能有独特的问题，在笔记本电脑和OpenGL中比较常见。譬如笔记本电脑使用的Intel GMA（Graphics Media Accelerator）核芯显卡系列就常与OpenGL出问题。

如果不知道怎么做，请搜索相关教程。

# = 软件 =
与Minecraft无关的软件也可能会导致游戏崩溃。Windows下最有可能的软件是用户账户控制（User Account Control，UAC），不同类型的反恶意软件（如防毒，防火墙），如果最近安装了应用程序（特别是防毒软件），尝试停用它。如Minecraft不再崩溃，这个软件很可能是问题的源头。可将Minecraft的文件夹和可执行文件添加到其排除项，或考虑将其移除（出于安全原因不推荐）。

如果不知道怎么做，请搜索相关教程。

# = Java =

使用与游戏不兼容的Java（如使用Java 8启动[21w19a](21w19a.md)之后的版本），或者使用与自己的操作系统不兼容的Java也可能导致崩溃。

游戏版本对应的所需Java版本可参阅。若要下载Java，请[Oracle官网](https://www.oracle.com/cn/java/technologies/downloads)或者[Adoptium官网](https://adoptium.net/zh-cn/)。

# = 手动触发 =
玩家可同时按住10秒手动触发一次调试性崩溃，并生成Minecraft崩溃报告。这个功能用于调试，而且是最安全的崩溃。

按住10秒会强制Java虚拟机崩溃，生成虚拟机崩溃报告，而不是常规的Minecraft崩溃报告。
* 对于某些键盘，它只能使用右侧触发，而使用左侧只会产生普通的崩溃。

# = 内存不足 =
如果玩家的空闲内存（RAM）很低，Minecraft可能也会崩溃。如果是这种情况下的崩溃，玩家可能需要添加更多的内存或关闭其他占用大量内存的线程。

# = 游戏内 =
进行有崩溃风险的操作，例如激活一个[每个面都是活塞臂的活塞](Java版已移除方块#六面共用纹理的方块.md)，或引爆大量[TNT](TNT.md)，都将会生成大量的线程使游戏崩溃。对更新抑制器施加不由玩家直接引起的[方块更新](方块更新.md)，也必定导致崩溃。

# == 标记实体 ==
一个被标记的[实体](实体.md)也可能使游戏崩溃，无论是原版游戏还是[修改过的](Mod.md)。最罕见的崩溃类型是一个被标记的[方块实体](方块实体.md)。

# = 存档文件夹/目录中有无法识别的符号 =
在文件夹/目录上出现了游戏或系统无法识别的符号也可能导致崩溃。

这一点常出现于编码有错误的文件系统或ext文件系统中。<ref group="注">ext文件系统允许除了<code>$'\000'</code>（U+0000，NULL）与<code>/</code>两个字符的任何字符作为文件名，因此有些字符会因为编码错误或字体渲染错误而导致崩溃。</ref>

# = 文件系统权限 =
在Linux中，将存档等文件或目录的读取权限去除（通常包括去除r权限、更改文件所有者）、写入权限去除（通常包括去除w权限、更改文件所有者、添加i属性）、目录访问权限去除（通常包括去除x权限、添加i属性），则在读取/写入存档时，随时有可能因IO错误或文件系统错误而崩溃。

# = 进程被结束 =
在Linux系统上，向Minecraft进程发送SIGTERM、SIGKILL等信号（通常使用Linux命令kill或killall发送）会使游戏崩溃。最常见的情况是进程占用内存过高而被[OOM Killer](https://www.kernel.org/doc/html/latest/admin-guide/mm/concepts.html?highlight=oom+killer#oom-killer)杀死。

以这种方式崩溃的游戏有时不会生成崩溃报告（生成崩溃报告前进程就被结束了）。

# 崩溃报告中诙谐的评论

在崩溃报告中会出现“诙谐的评论”，这些评论出现在崩溃报告上的第二行。它们被硬编码在<code>net.minecraft.CrashReport</code>中。这些文字在分析崩溃报告时没有作用。

# Hopper
* *Hopper**<ref>http://hopper.minecraft.net/</ref>是一个非公开可见的崩溃报告工具，由Mojang管理、储存、维护崩溃报告。它最初只用于提供排除Minecraft故障的技术性信息。<ref>http://hopper.minecraft.net/help/</ref>

2019年，Hopper的帮助页面移动至[minecrafthopper.net](https://minecrafthopper.net)，原先的页面现在全部重定向至新的网站。这个新网站由社区维护，任何人都可以在其[GitHub仓库](https://github.com/MinecraftHopper/MinecraftHopper)上提交贡献。
