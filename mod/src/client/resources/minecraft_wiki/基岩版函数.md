# 基岩版函数

*页面ID: 54538* | *来源: Minecraft Wiki*

* *函数（Function）**是一种可包含多行[命令](命令.md)的<samp>.mcfunction</samp>文本文件，存储于[行为包](行为包.md)中的{{filepath|-{}-<行为包>/functions}}目录下，可以用于方便地执行多条命令。

# 定义
# = 文件夹结构 =

原版默认无任何函数。要使用函数，首先必须在游戏文件根目录中的或中创建一个[行为包](行为包.md)；如果是多人游戏，函数必须放置在每一个需要使用该函数的世界存档文件夹中。

像其他的文件一样，文件夹也能包含若干子文件夹以组织更深的层级关系。在调用这些子文件夹内的函数时，也必须引用子文件夹名。例如，如果需要调用{{filepath|-{}-behavior_packs/<行为包文件夹名称或.zip文件名称>/custom/functions/example/test.mcfunction}}的函数文件。则需描述为<code>custom:example/test</code>。

# = 文件结构 =
# == <samp>.mcfunction</samp>文件 ==
* *单行命令**

在<samp>.mcfunction</samp>文件中，每一行都允许一条不带前导正斜杠的命令。可以在每条命令的行首行末添加若干制表符或空格——在读取函数文件时，每行的首尾空白字符都会被消去。在函数文件中，单个命令的长度不受命令方块字符数上限32,500的限制。基岩版目前暂不支持类似[Java版](Java版函数#文件格式.md)的单行命令的拆分和续接。

* *注释**

目前函数文件仅支持单行注释，玩家可以在行首添加来注释单行文本。

# == <samp>tick.json</samp> ==
可以重复运行一系列函数。

其使用每秒20刻的游戏刻，即设置运行的函数将每秒执行20次。因此包含大量要运行的函数会严重影响性能，尤其是在低端设备中。

文件仅使用键，值是要运行的函数的名称。以下是一个示例：
<syntaxhighlight lang="json">
{
    "values": [
        "a",
        "b"
    ]
}
</syntaxhighlight>

游戏会尝试每秒运行20次名为和的<samp>.mcfunction</samp>文件。

# = 命令版本 =

需要在[行为包](行为包.md)内的文件中使用声明函数适用的最低版本，此字段叫做最小引擎版本。

该字段指定了运行命令的游戏版本的版本号。例如，命令在[1.16.210](基岩版1.16.210.md)中发生了变动，如果你的行为包带有<code>"min_engine_version": [1, 8, 0]</code>，那么在运行包含的函数时，游戏将视其为旧版本的命令来运行，就如同游戏版本仍为[1.8.0](基岩版1.8.0.md)。

需要注意，中的<code>format_version</code>会影响最小引擎版本的读取方式。当<code>format_version</code>为<code>1</code>时，最小引擎版本最高为[1.12.0](基岩版1.12.0.md)；当<code>format_version</code>为<code>2</code>时，最小引擎版本最低为[1.13.0](基岩版1.13.0.md)。例如，如果填写了<code>"format_version": 1</code>和<code>"min_engine_version": [1, 19, 50]</code>，那么最小引擎版本将被读取为[1.12.0](基岩版1.12.0.md)而非[1.19.50](基岩版1.19.50.md)。

# 调用
函数可能以不同的方式从行为包中的其他文件调用。

# = 通过命令 =
可以使用命令调用函数。

# = 通过计划 =
命令可推迟函数在一定时间后被调用，或在指定的区域全部被加载时执行一个函数。函数将在满足到达后由服务端自动执行，执行位置为世界出生点。

# 行为
# = 加载与解析 =
在正在运行的存档中，如果对函数文件的内容或位置进行了修改，则可以使用来重新从硬盘加载。

在进入存档时，游戏会对函数文件进行预读取，若命令中出现了语法错误，游戏将会在内容日志中弹出报错并取消加载，进入存档后将无法在[聊天栏](聊天栏.md)或[命令方块](命令方块.md)中使用含有语法错误的函数文件。

# = 运行 =
目前的函数支持检测的特定条件极为有限，因为函数按照顺序执行命令，等命令不能起到作用。要解决这个问题，可以设置函数的最低引擎版本为[1.19.50.23](基岩版1.19.50.23.md)或更高，然后使用类似于[Java版](Java版.md)中的命令unless) ...}}。

函数每次被调用时，都将在一[游戏刻](游戏刻.md)内运行其中的所有命令，包括其中通过命令执行的子函数，也将在同一个游戏刻运行。同一游戏刻运行的总命令数量受[游戏规则](游戏规则.md)的限制（默认为10000）。超过此数量限制的命令将在运行时被忽略。

在单人或局域网世界中，与命令方块一样，函数可以执行任何[权限等级](权限等级.md)不超过1的命令。

在默认的多人游戏，函数要运行的命令的权限等级不能超过设定在中的。

使用命令运行函数时，函数内部的命令会继承命令的[命令上下文](命令上下文.md)中的“执行者参数”、“执行环境参数”和“执行权限等级”，不会继承“执行输出反馈”。

通过命令计划的函数也会继承此命令执行上下文中的“执行者参数”、“执行环境参数”和“执行权限等级”

例如以下函数：
<syntaxhighlight lang="mcfunction">
execute as @a at @s run function foo:bar
</syntaxhighlight>

其中*foo:bar*的内容是：
<syntaxhighlight lang="mcfunction">
teleport @s ~ ~5 ~
execute at @s run setblock ~ ~-1 ~ minecraft:diamond_block
setblock ~ ~-1 ~ minecraft:emerald_block
</syntaxhighlight>

以上命令执行成功后，所有玩家都将被向上传送5格，并在其传送前脚下的位置放置绿宝石块。由于第2条命令使用的<code>at</code>子命令改变了其位置参数，故钻石块会被放置在传送后的位置。
