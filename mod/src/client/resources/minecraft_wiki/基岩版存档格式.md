# 基岩版存档格式

*页面ID: 92029* | *来源: Minecraft Wiki*

基岩版使用了修改后的Google的LevelDB（Zlib压缩格式）来储存存档格式资料。

# 基于LevelDB的格式
# = Mojang的LevelDB格式 =
Mojang修改了谷歌的[原始LevelDB](https://github.com/google/leveldb)以加入对Zlib压缩格式的支持。代码可以在[Github页面](https://github.com/Mojang/leveldb)的main分支访问，且编写指引由Tommaso在[此处](https://twitter.com/_tomcc/status/477950809427427328)提供。

对于Java版的LevelDB + Zlib，请见[此Github页面](https://github.com/tinfoiled/leveldb)。

Google的leveldb库自从Mojang在发布Minecraft后得到了极大的改变，但Mojang自己修改后的版本仍然可以独立运作，但代码需要一些小修改来实现兼容性：

数据库储存在db或基岩版世界的子目录。传递给LevelDB API的数据库路径是这个路径，而不是其中任何文件的路径。这似乎也是存储世界地形的位置，因为可以通过将其db文件夹替换为来自无限世界类型的文件夹来将[旧世界类型](旧世界类型.md)变为无限。

# = 区块键值格式 =
有关区块数据的数据库键是以下内容的并列：
* 两个带符号的32位小端序<!-- little-endian -->整数（x和z分别位于区块坐标中）。
* 可选的第三个32位小端序整数（1为[下界](下界.md)，2为[末地](末地.md)，忽略掉则为[主世界](主世界.md)）。
* 一个单字节标签，指定键所代表的记录类型（见表），以及……
* （对于SubChunkPrefix记录）一个字节的子区块索引（从0到15）。

因此，这些键值应当为9、10、13或14字节长度。对于指定的区块而言，并非所有子区块都需要存在。

、和记录代表了[NBT](NBT.md)变种中的串联根标签序列，它以短整数格式存储长度和多字节整数类型，而不是或原始NBT规范使用的大端序<!-- big-endian -->格式。

中的零值用于记录旧世界格式，更高的值被无限世界类型使用。

# = 其余键值 =
实体数据存在特殊键值来储存本地玩家实体数据。如果这里存在实体数据，则它优先于存储在level.dat中的玩家数据。与关联的数据值使用NBT格式在父级根目录里有且只有一个复合标签。

同时存在一个用于远程控制玩家的特殊键值，它由两个部分组成。第一个部分是前缀，第二部分是客户端ID，包含了远程遥控玩家的clientid.txt文件。例如，是使用客户端ID为的控制远程客户端的键值。与前缀键值关联的值是一个NBT结构文件，并且在根级别只有一个复合标签。

对于保存的结构，键值以为前缀，结构的命名空间及名字附加在其后，例如便是即默认命名空间下的结构。

此外，也有一个名为的长度为20的键值，被超平坦世界使用。与此键关联的值是一组ASCII文本格式的数字。与键关联的值的例子是，值长度为9。

一些键值与村民有关：
* VILLAGE_[0-9a-f\\-]+_DWELLERS
* * 主要由实体/生物ID组成。包括村民、铁傀儡和猫。
* VILLAGE_[0-9a-f\\-]+_INFO
* * 包含了村庄边界。
* VILLAGE_[0-9a-f\\-]+_POI
* * 包含了村民和工作站点之间的映射，以及村民在认领职业时的初始化事件、与工作方块交互时的碰撞箱模式和声音事件等等，声音事件默认为。床位分配似乎没有被存储。
* VILLAGE_[0-9a-f\\-]+_PLAYERS
* * 包含了村庄对于单个玩家的声望值，对应玩家ID和声望值S。

# level.dat
level.dat为NBT格式。相比于其他NBT，level.dat在开头多出了两个4字节整数。第一个整数是基岩版存储工具版本，当前为10。第二个整数是level.dat的大小。
