# Java版函数

*页面ID: 29976* | *来源: Minecraft Wiki*

* *函数（Function）**是一种可包含多行[命令](命令.md)的<samp>.mcfunction</samp>文本文件，存储于[数据包](数据包.md)中的{{filepath|-{}-data/<*命名空间*>/function}}目录下，可以用于方便地执行多条命令。

# = 目录结构 =
原版数据包中默认无任何函数。要使用函数，首先必须在存档文件夹的目录中定义一个[数据包](数据包.md)。世界存档文件夹位于{{filepath|-{}-[.minecraft](.minecraft.md)/saves/<*存档名称*>}}；如果是多人游戏，函数必须放置在每一个需要使用该函数的世界存档文件夹中。

要在数据包中定义一个函数文件，可参照下图：

以上的文件夹结构定义了一个命名空间ID为<code>-{}-<*命名空间*>:<*函数名称*></code>的函数。

像其他的数据包文件一样，文件夹也能包含若干子文件夹以组织更深的层级关系。在调用这些子文件夹内的函数时，也必须引用子文件夹名。
例如，如果需要调用{{filepath|-{}-datapacks/<数据包名称>/data/custom/function/example/test.mcfunction}}的函数文件。则需描述为<code>custom:example/test</code>。

# = 文件格式 =
* *单行命令**

在文件中，每一行都允许一条不带前导正斜杠的命令。可以在每条命令的行首行末添加若干制表符或空格——在读取函数文件时，每行首尾的空白字符都会被忽略。在函数文件中，单个命令的长度不受命令方块字符数上限32,500的限制。

* *单行命令的拆分和续接**

对于一行命令，如果在末尾使用反斜杠，则允许在下一行添加后续部分。后续行的前后两端的空白会被截去后连接在上一行命令后。这提供了一种将单行命令拆分为多行书写的方法。

例如以下命令：
<syntaxhighlight lang="mcfunction">say 你 \
    好</syntaxhighlight>

会进行连续拼接：<code>say 你</code>与<code>好</code>进行拼接，最终得到单行命令：<code>say 你好</code>。

* *注释**

目前函数文件仅支持单行注释，玩家可以在行首添加来注释单行文本。

# = 宏 =
* *宏（Macros）**将函数中的命令解析过程延迟到运行时，并允许在解析前动态地改变命令中的各部分。

将函数中的一行以开头（作为首个非空白字符），即可标记这一行为宏命令，同时所在函数也将成为宏函数；宏命令还必须以<code>-{}-$(<*键*>)</code>的形式包含一个或更多的替换段。例如以下宏函数共有1条宏命令，其中包含2个有效替换段：

* <code>abcdefghijklmnopqrstuvwxyz</code>，26个小写英文字母。
* <code>ABCDEFGHIJKLMNOPQRSTUVWXYZ</code>，26个大写英文字母。
* <code>0123456789</code>，数字。
* <code>_</code>，下划线。

由于每条宏命令实际上最终都将被替换为一个普通命令并解析执行，所以若其中的一条在替换后无法形成有效命令也会导致整个所在函数解析失败。

若调用非宏函数使用复合标签，则会忽略而不报错。

# = 通过函数标签 =
多个函数可以通过[数据包](数据包.md)中的[标签](Java版标签.md)组合到一起。标签中的函数将以其定义顺序从上到下依次执行，如果同一函数在标签中多次出现，则只在首次出现时执行。

如上文所述，可以命令来主动调用一个函数标签包含的若干函数。除此之外，在命名空间下包含了两个拥有特殊行为的函数标签：
* 在标签中列出的函数将在世界加载时或者服务器被启动时执行。每当数据包重载时，这些函数也将被执行。
* * 除了在数据包重载时执行外，这些函数执行的时间早于玩家进入世界的时间，因此无法使用[目标选择器](目标选择器.md)来找到玩家，诸如和命令将不会为任何玩家显示消息。
* 在标签中列出的函数将在每一刻开始时执行。随着游戏刻递增，这些函数持续反复执行。

# = 通过计划 =
命令可推迟函数在一定时间后被调用。函数将在其计划时间到达后由服务端自动执行。

# 行为
# = 加载与解析 =
在正在运行的存档中，如果对函数文件的内容或位置进行了修改，则可以使用来重新从硬盘加载。

在每次打开存档或打开服务器时，游戏也会尝试加载数据包中的函数。

在函数加载时，其中的所有的非宏行都会被作为命令解析，如果其中任意一行命令无法解析，则此函数无法加载。宏行则只有在每次此函数被调用时才会被解析为命令。

# = 运行 =
在单人或局域网世界中，与命令方块一样，函数可以执行任何权限等级不超过2的命令。

在默认的多人游戏，函数要运行的命令的权限等级不能超过设定在中的。

函数每次被调用时，都将在一[游戏刻](游戏刻.md)内运行其中的所有命令，包括其中通过命令执行的子函数，也将在同一个游戏刻运行。同一游戏刻运行的总命令数量受[游戏规则](游戏规则.md)的限制（默认为65536）。超过此数量限制的命令将在运行时被忽略。

函数将当前函数调用者的参数（包括命令的执行实体，以及执行位置、朝向、维度和基准点）存储到执行上下文（execution context）中，并将其中的上下文其提供给每条命令。在同一函数内，命令可以改变当前命令的上下文，但不会传递该影响到之后的任何命令。若为执行者为服务端（名称显示为“Server”），则执行位置为世界出生点。

例如以下函数：
<syntaxhighlight lang="mcfunction">
execute as @a at @s run function foo:bar
</syntaxhighlight>
其中*foo:bar*的内容是：
<syntaxhighlight lang="mcfunction">
teleport @s ~ ~5 ~
execute at @s run setblock ~ ~-1 ~ minecraft:diamond_block
setblock ~ ~-1 ~ minecraft:emerald_block
</syntaxhighlight>
以上命令执行成功后，所有玩家都将被向上传送5格，并在其传送前脚下的位置放置绿宝石块。由于第2条命令使用的<code>at</code>子命令改变了其位置参数，故钻石块会被放置在传送后的位置。

# = 返回 =
函数的返回机制主要由命令实现。在函数中，若某条命令执行后，则该函数将被强制中断，其之后的所有命令都将不再被执行。若命令接在unless) ... run}}后或其他可能[执行中断](命令/execute#执行分支.md)的命令之后，则可能因的中断而不被执行，故可利用此机制，限制命令仅在特定条件下执行。这样，函数就可以在不同的条件下（也即在不同的位置）结束，从而实现更复杂的行为。

命令可以设置函数的返回结果。函数的返回结果主要由2个参数组成：
* 成败标志：为一个布尔值，为成功，为失败。
* 返回值：为一个整型数值。例如在执行函数时输出的提示信息：“”中的42就是这个函数的返回值。

不同的命令将造成不同的返回结果。若函数中不存在命令，则该函数没有任何返回结果，可称为**Void函数**。

如果函数被命令调用，其返回结果将返回至命令，并作为其输出值输出。

如果函数被unless) function}}命令调用，将会判断其函数返回值存在且非0。
