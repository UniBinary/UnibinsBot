# 命令上下文

*页面ID: 125751* | *来源: Minecraft Wiki*

* *命令上下文（Command Context）**，也称**执行上下文（Execution Context）**、**命令<!--commands.schedule.invalidOrigin-->（Command Origin）**、**命令来源堆叠（Command Source Stack）**，是调用者和调用环境等参数构成的集合，用于为[命令](命令.md)执行和[文本组件](文本组件.md)解析提供上下文。

# 行为
命令上下文中主要有以下/个参数：
* **[执行权限等级](#执行权限等级.md)**
* 执行者（Executor）参数，包括：
* * **[执行者名称](#执行者.md)**
* * **[执行者实体](#执行者.md)**
* 执行环境参数，包括：
* * **[执行维度](#执行维度.md)（Execution Dimension）**
* * **[执行位置](#执行位置.md)（Execution Position）**
* * **[执行朝向](#执行朝向.md)（Execution Rotation）**
* *
* **[执行输出反馈](#执行输出反馈.md)**

游戏在不同场景下执行[命令](命令.md)或解析[文本组件](文本组件.md)时，会为其提供相应的上下文，以使其可以在特定的环境下生效。

使用命令运行函数时，函数内部的命令会继承命令执行上下文中的“执行者参数”、“执行环境参数”和“执行权限等级”，不会继承“执行输出反馈”。单人与局域网游戏中函数内命令的“执行权限等级”被限制在2及以下，即使命令以2级以上的权限执行，函数内的命令也只会以2级执行。服务器中可以通过[服务端配置文件](服务端配置文件.md)来更改此权限。

通过命令计划的函数也会继承此命令执行上下文中的“执行者参数”、“执行环境参数”和“执行权限等级”。

# = 动态参数 =

上下文中的“执行者名称”参数和各个执行环境参数都是静态的，各自都独立存在。也就是说，若不使用的子命令修改，在执行命令过程中、或在执行函数中的各条命令过程中，这些参数不会改变。例如，即使在函数内中途修改了执行者实体的名称，也不会改变后续命令的上下文中的“执行者名称”参数；再例如，，即使在函数内中途使用改变了羊的位置、朝向或维度，也不会影响函数中后续命令的上下文中的“执行位置”、“执行朝向”、“执行维度”参数，这三个参数在使用子命令修改后是静态的，与羊实体本身已经无关联。

上下文中的参数有些情况下是静态的，有些情况下是动态的，从某个实体身上实时获取。例如，“执行位置”参数可能并不独立存在，而是依赖于世界中的某个实体，实时获取其位置，也就是说，此时若在函数的中途移动了这个实体，则函数中后续命令的上下文中的“执行位置”参数是移动后的位置。<ref>参见</ref>

具体来说，以下情形下存在动态参数：
* 玩家在聊天栏执行命令、通过客户端的WebSocket服务器请求执行命令的上下文中，执行位置、执行朝向和执行维度是动态的，从此玩家实体上实时获取。
* 命令方块矿车执行命令的上下文中，执行位置和执行朝向是动态的，从此矿车实体上实时获取。
* 在实体事件响应中执行命令、在脚本中以实体执行命令、实体在行为包动画控制器中执行命令、NPC执行命令的上下文中，执行者名称、执行位置、执行朝向和执行维度是动态的，从此实体上实时获取。
* 命令会使执行者名称转变为动态参数，从执行者实体上实时获取。也就是说，无论上下文中是否有静态的执行者名称，使用命令执行命令时，执行者名称总是动态的，从执行者实体上实时获取。
* 的和子命令设置的执行位置是动态的，从其指定的实体上实时获取。
* 的和子命令设置的执行朝向是动态的，从其指定的实体上实时获取。

执行位置若是动态的，则实时获取某个实体的位置。如果此实体[骑乘](骑乘.md)了其他实体，则有特殊处理：
* 如果此实体的碰撞箱底部低于坐骑的碰撞箱底部，则使用坐骑的碰撞箱底部坐标作为执行位置的Y坐标。
* * 例如，玩家骑乘在矿车上，则使用玩家的X和Z坐标与矿车的Y坐标，作为执行位置。

若动态上下文参数所依赖的实体已经从世界中消失（例如盔甲架被杀死、羊播放完死亡动画），则此参数无法正常获取，此时使用的参数默认值如下：
* “执行者名称”是空字符串
* “执行维度”为空
* “执行位置”是<code>(0, 0, 0)</code>
* “执行朝向”是<code>(0, 0)</code>
例如，在命令方块中执行，如上文所述，“执行者名称”被命令转变为动态，从“执行者实体”上实时获取。由于上下文中没有“执行者实体”，故的“执行者名称”是空字符串。

再例如，在计划还未执行前杀死执行者实体，会由于上下文中的“执行维度”为空而无法执行计划的函数。

以下情形下会使得动态参数转变为静态参数：
* 命令本身会使执行维度静态化
* 命令本身会使执行朝向静态化
* 的子命令会使执行位置静态化
* 的子命令会使执行位置静态化
* 的{{cd|-{}-positioned <*坐标*>}}子命令会使执行位置静态化
* 的子命令会使执行朝向静态化
* 的{{cd|-{}-rotated <*角度*>}}子命令会使执行朝向静态化
* 如果执行位置是动态的，则的子命令会使执行位置静态化，设置为实体脚部或眼部的位置；如果执行位置是静态的，则不生效<ref>参见和</ref>

例如：
* 玩家在聊天栏执行，函数中各个命令的执行位置、执行朝向和执行维度是动态的，实时获取此玩家的位置、朝向、维度。
* 玩家在聊天栏执行，{{cd|-{}-<*命令*>}}的执行位置是动态的，执行朝向和执行维度是静态的。
* 玩家在聊天栏执行，{{cd|-{}-<*命令*>}}的执行位置和执行朝向是动态的，执行维度是静态的。
* 玩家在聊天栏执行，{{cd|-{}-<*命令*>}}的执行位置是动态的，执行朝向和执行维度是静态的。
* 玩家在聊天栏执行，{{cd|-{}-<*命令*>}}的执行位置、执行朝向和执行维度都是静态的。
* 玩家在聊天栏执行，{{cd|-{}-<*命令*>}}的执行位置、执行朝向和执行维度都是静态的。
* 假如玩家所在维度上有至少三个实体，玩家在聊天栏执行，会使玩家传送到原位置的上方3格。

# 参数
# = 执行权限等级 =

执行权限等级不可使用命令修改。

使用命令运行函数时，函数内命令的执行权限等级会被限制在2及以下。执行权限等级如果大于2，函数内的命令会以2级执行。

# = 执行者 =
执行者是执行命令的主体。包括“执行者名称”和“执行者实体”两个参数，其中“执行者实体”参数可能为空（如使用命令方块执行命令时）。主要有以下情形会使用执行者参数：

* 使用、等命令发送消息时，会使用“执行者名称”参数作为消息的发送者。
* [目标选择器](目标选择器.md)中的<code>@s</code>会直接选择“执行者实体”。
* 、等命令的目标实体默认为“执行者实体”。
* 、、等命令的目标玩家默认为“执行者实体”，要求“执行者实体”为玩家。
* 、等命令会以“执行者实体”的身份生效，且要求“执行者实体”为玩家。
* [执行锚点](#执行锚点.md)对Y轴坐标的修改基于执行者实体的眼睛高度。

执行者参数可以使用命令的、和子命令修改。执行者名称和执行者实体两个参数会同时修改。只会修改执行者实体参数，如上文所述，执行者名称会保持动态，从执行者实体上实时获取。

# = 执行维度 =
执行命令所在的[维度](维度.md)。主要有以下情形会使用执行维度参数：
* 凡是指定[坐标](坐标.md)时，指定的都是执行维度内的坐标。
* [目标选择器](目标选择器.md)在指定了<code>distance</code>、<code>r</code>、<code>rm</code>、<code>dx</code>、<code>dy</code>或<code>dz</code>时，则只会选择执行维度内的实体。
* [目标选择器](目标选择器.md)在指定了<code>x</code>、<code>y</code>或<code>z</code>时，也只会选择执行维度内的实体。
* 等命令在执行维度内运行。

执行维度可以使用命令的和子命令修改。命令本身会使执行维度静态化。

# = 执行位置 =
执行命令所在的[坐标](坐标.md)。主要有以下情形会使用执行位置参数：
* [相对坐标](坐标#命令.md)会以执行位置为原点。
* [局部坐标](坐标#命令.md)在执行位置的基础上，根据执行锚点改变其原点。
* [局部坐标](坐标#命令.md)以执行位置为原点。
* 和在执行位置的基础上，根据执行锚点改变其起点。
* 和以执行位置为起点。
* 等命令会使用执行位置作为起点。
* 、、等命令中，如果未指定命令生效的位置，则使用执行位置。

执行位置可以使用命令的、、子命令修改，子命令也会影响执行位置。和子命令设置的执行位置是动态的，从其指定的实体上实时获取。、、和{{cd|-{}-positioned <*坐标*>}}子命令会使执行位置参数静态化。

# = 执行朝向 =
执行命令所朝向的方向。主要有以下情形会使用执行朝向参数：
* [局部坐标](坐标#命令.md)的坐标系基于执行朝向。
* 、等命令中以波浪号（）指定相对朝向时，以执行朝向为基准。

执行朝向可以使用命令的、和子命令修改。和子命令设置的执行朝向是动态的，从其指定的实体上实时获取。命令本身和其、{{cd|-{}-rotated <*角度*>}}子命令会使执行朝向静态化。

# = 执行锚点 =

[局部坐标](局部坐标.md)的原点、的的起点和的子命令的起点是基于执行者实体的脚还是眼睛。
* 如果是脚，则直接使用执行位置。
* 如果是眼睛，则在执行位置的基础上，Y轴加上执行者实体的眼睛高度。

只有以下情形会使用执行锚点参数：
* [局部坐标](局部坐标.md)的中心。
* 的子命令的起点。
* 的起点。
* 的起点。

执行锚点可以使用命令的子命令修改。

没有执行锚点参数。命令的子命令直接修改执行位置。如果执行位置原本是动态的，则子命令会使执行位置静态化，设置为实体的脚部或眼部的位置；如果执行位置是静态的，则子命令没有任何效果。

# = 执行输出反馈 =
执行输出反馈用于接收命令的[输出](命令#输出.md)。

在[命令方块](命令方块.md)、[命令方块矿车](命令方块矿车.md)中执行命令时，会接收命令的成功次数。

可以使用命令的子命令保留已有反馈的同时添加新反馈。已有的反馈无法使用命令清除。

使用命令或运行函数时，函数内命令的执行不会继承其执行输出反馈。

使用NBT修改[告示牌](告示牌.md)中文本时的上下文：
* 执行权限等级：2
* 执行者名称：<code>Sign</code>
* 执行者实体：无
* 执行维度：告示牌所在的维度
* 执行位置：告示牌所在方块的正中心
* 执行朝向：<code>(0, 0)</code>
* 执行锚点：脚
* 阅读者：无

# == 文本展示实体 ==

[文本展示实体](文本展示实体.md)解析文本组件时的上下文：
* 执行权限等级：2
* 执行者名称：此文本展示实体的名称
* 执行者实体：此文本展示实体
* 执行维度：文本展示实体所在的维度
* 执行位置：文本展示实体所在的位置
* 执行朝向：文本展示实体的朝向
* 执行锚点：脚
* 阅读者：此文本展示实体

# == 物品修饰器 ==

[物品修饰器](物品修饰器.md)的<code>set_name</code>和<code>set_lore</code>，如果其指定的实体存在，则进行文本组件解析：
* 执行权限等级：2
* 执行者名称：指定的实体的名称
* 执行者实体：指定的实体
* 执行维度：指定的实体所在的维度
* 执行位置：指定的实体所在的位置
* 执行朝向：指定的实体的朝向
* 执行锚点：脚
* 阅读者：指定的实体
