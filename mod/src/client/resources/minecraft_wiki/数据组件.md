* *数据组件（Data Component）**<ref></ref>，或简称为**组件（Component）**，是用于定义和存储各种数据属性的结构化数据。

由于[物品堆叠](物品堆叠.md)全面使用数据组件格式，故其也被称为**物品堆叠组件（Item Stack Component）**或**物品组件（Item Component）**。<ref name=24w09a></ref>

# 行为
数据组件是结构化的数据，也即每一个组件都有自己独特的编码方式。如果组件的数据格式不正确，则游戏会立即解析失败，对应的命令和文件等全部无效。

由于数据组件的编码解码行为，使得其与通常的[NBT标签](NBT标签.md)数据不同。通常的NBT标签仅会在游戏尝试序列化为程序对象时才判断其是否符合编码格式，而组件自游戏加载之初就进行了判断。这使得数据组件格式拥有更快的加载性能，可以更早地发现命令和文件中的潜在错误。<ref name=24w09a/>

除了编码方式外，每一个组件都有是否持久化和是否同步两个基本性质。不可持久化的组件通常仅用于网络传输，随游戏计算完毕或内存卸载而移除，不会保存到[存档](存档.md)里，强行加载和保存也会导致游戏解析失败。若无特殊说明，下文的组件均指持久化组件。

# = 加载行为 =
物品堆叠、方块实体和实体可以拥有数据组件。

目前方块实体和实体依然使用了非结构化的NBT标签存储。为了对方块实体或实体套用或获取数据组件，游戏会将对应的组件和对应的NBT标签绑定。这步绑定操作所用的组件在游戏内部被称为隐式组件（Implicit Component）。游戏通常在使用物品放置方块或实体时套用组件，而使用谓词检测或破坏方块时获取组件。

例如：当使用命名过的箱子放置箱子时，箱子物品的<code>custom_name</code>组件会套用到箱子的方块实体上。而方块实体会使用方块实体数据来保存它。而当从箱子获取<code>custom_name</code>组件时，游戏会将方块实体数据视为<code>custom_name</code>组件。

# = 物品堆叠 =

物品堆叠全面使用数据组件格式。虽然游戏为每个物品定义了依据物品类型的默认组件，但默认组件只在内存中计算，不会保存到存档中。而存档会存储物品的组件修订（Data Component Patch）数据，组件修订中指定的组件会覆盖默认组件的值，且带<code>!</code>前缀的组件会移除该物品的默认组件。

绝大多数数据组件都对物品自身有实际作用，决定了物品的诸多性质，例如是否可堆叠、可损坏等，影响了大量的游戏行为。当以组件为单位修改物品时，游戏不允许物品同时具有<code>damage</code>组件和值大于1的<code>max_stack_size</code>的组件补丁，即物品不可以既可堆叠又可损坏。

# 命令格式
<code>item_stack</code>和<code>item_predicate</code>[参数类型](参数类型.md)支持物品堆叠组件。

<code>item_stack</code>参数类型可以加载物品组件，也可通过在组件名前添加<code>!</code>来移除该物品的默认组件，在等命令中使用。所提供的组件都会被设置，而未提供的组件会被设为默认值。格式参见。

<code>item_predicate</code>参数类型可以检测物品组件，在等命令中使用。另外，该参数类型还可以直接使用[数据组件谓词](数据组件谓词.md)检测物品堆叠组件。格式参见。

# = profile =
存储玩家的头的对应玩家的游戏档案数据。

游戏会优先使用玩家档案获取皮肤等数据，然后再根据玩家皮肤指定的纹理模型等进行更改。例如游戏渲染玩家的头<code>player_head[profile={name:"jeb_", texture:"missingno"}]</code>时，会先获取玩家jeb_的皮肤，再使用无效纹理进行覆盖。

如果设置了，则游戏直接使用此游戏档案数据，不会因为对应玩家档案的更改而更改。

在未设置的条件下，如果设置了，则游戏会将其视作玩家名称解析游戏档案。如果设置了，则游戏会将其视作UUID解析游戏档案，解析的优先级高于。游戏并不会将获取的游戏档案数据存储，而是实时获取，尽管需要客户端重新启动才能更改渲染效果。此时物品提示框也会显示“”，以与静态游戏档案相区分。

无论是静态档案还是动态档案，只有会影响玩家的头的物品名称。

如果设置此组件为字符串，则等价于只设置复合标签形式中的，游戏在保存时只会保存为复合标签形式。

<div class="treeview">
*
* *
</div>
